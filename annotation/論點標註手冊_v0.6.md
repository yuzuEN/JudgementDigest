# 台灣判決書論點標註手冊 v0.6

標註判決理由中「法院在做什麼」的規則。以 AI 為主要標註者，人工依線索抽查。

## v0.6 的修訂摘要

v0.5 的抽查：CONCL、PROC 25/25，RULE、DAM 23/25，SUB 22/25，EV 19/23；EXP 照封閉清單只有 10/25，
但錯誤幾乎都是清單用語的同義變化（常情、社會通念）。v0.6 處理三類問題：
**標籤之間的邊界**（PROC／RULE／SUB、EV／BOP／SUB、DAM／SUB）、**EXP 的定義方式**、**長引文被截斷**。

| 項目 | v0.5 | v0.6 | 依據（v0.5 抽查的 sample_id） |
|---|---|---|---|
| **PROC** | 程序處分標 PROC | 引用程序法條並在本案做出處分，**只標 PROC，不另標 RULE 或 SUB** | 同一句雙標：RULE 3044、3066；SUB 3093、3234；EV 3028 |
| **EV** | 評價證據或依證據推論 | **必須有被評價的具體證據**；只有評價語氣 → BOP、SUB 或不標 | EV 3022、3101、3112；不確定 3126、3155 |
| **SUB** | 只收定性 | 先看**主詞**：抽象 → RULE；只認定事實 → EV／UNC；「自得請求」屬 SUB | SUB 3279、3286、3241 |
| **DAM** | 金額的裁量 | 過失相抵在**要件階段就不成立 → SUB**，不是 DAM | DAM 3202、3230；RULE 3098 |
| **EXP** | 逐字封閉清單 | **開放的功能定義**：以一般經驗、常情、社會通念為判斷依據；手冊只舉例 | EXP 15 筆同義變化（3261、3263、3285 等） |
| **CONCL** | 方向三類 | 方向依「**本段寫出的判斷**」 | CONCL 3122 |
| **BOP** | — | 補「舉證不足」「未提出證據以實其說」 | EV 3022、3088 |
| **規則 3（引文）** | 10–100 字 | 超過 100 字時寫「**開頭〔略〕結尾**」，結尾必須有完成動作的用語 | CONCL 長請求句被截斷約 10 筆；RULE 3071、SUB 3265 |
| 規則 11 | (A)–(E) | 新增 (F) 程序處分只標 PROC、(G) 先看主詞 | — |
| 驗證 | 7 類各 25 個 | 規則有改的 5 類各 25 個；RULE、CONCL 各 10 個回歸檢查；**可用門檻：95% CI 下界 ≥ 0.80** | 見第七節 |

**未改動的標籤**：RULE、CONCL（除方向判準外）、UNC、CL、HI、ADM、EQUITY、EXO、SENT 的定義與 v0.5 相同。

## 一、研究目的與標註單位

### 研究目的

分析不同法官在認定事實、評價證據、建立法律前提、量定刑度與賠償金額時的傾向差異；
標註結果同時供平台的判決導讀使用。

遇到邊界模糊時，回到這個問題判斷：**這段文字能不能告訴我們這位法官重視什麼？**

### 法律依據

| 規定 | 對應標籤 |
|---|---|
| 民訴§222 Ⅰ 證據力評價之自由 | EV 證據評價 |
| 民訴§222 Ⅱ 損害額之酌定 | DAM 給付額酌定 |
| 民訴§222 Ⅲ 經驗法則或論理法則 | EXP 經驗論理法則 |
| 證據能力有無 | ADM 證據能力（刑事） |

### 法學三段論與標籤的對應

| 步驟 | 法院在做什麼 | 標籤 |
|---|---|---|
| 大前提 | 陳述法律規範或其解釋 | **RULE** |
| 小前提 | 由證據認定事實 | **EV**（或 UNC：不爭執的事實） |
| 定性 | 把事實套入法律要件，得出該當與否 | **SUB** |
| 請求判斷（v0.5） | 對請求下結論：有理由／無理由 | **CONCL**（民事） |
| 法律效果的裁量 | 決定刑度或金額 | **SENT**（刑事）／**DAM**（民事） |

**CONCL 不算法官分析的一部分。** 它記錄的是判斷的結果，不是論證的理由：
分析法官論理傾向時排除 CONCL；CONCL 用在 D3，以及和判決結果自動比對。

### 標註單位（v0.5 修訂）

| | 範圍 | 切分方式 |
|---|---|---|
| **民事** | 組內資料庫 `sections.court`（法院判斷段） | **論點單位**：`annotation/structure.py` 的 `units(text, 1200)` |
| **刑事** | 理由全文 | 切段規則 v2；待刑事組的段落結構確定後再統一 |

**論點單位怎麼切**：依判決的編號層級（壹、→ 一、→ ㈠／(一) → ⒈／1. → ⑴／(1) → ①）解析成樹。
由上往下，一個節點（含所有子項）在 1,200 字內就整塊當一個單位；太長才拆成下一層；
沒有子編號又太長，才在句號處切。編號要通過位置與順序檢查，避免把「第一、二審」「1.5萬元」當成編號。

**3,000 件判決的測試結果**：

| | 組員的 400 字段落 | 論點單位（N=1,200） |
|---|---|---|
| 解析得出編號的判決 | — | 99.8% |
| 每件平均單位數 | — | 6.3 |
| 單位長度中位數 | — | 281 字 |
| 要在句號處硬切的單位 | — | 4.6% |
| 同一論點的大前提和結論落在同一單位 | 46.9% | **68%** |

**前後文**：只給相鄰單位的 300 字（前一單位的最後 300 字、後一單位的前 300 字），只用來理解脈絡。

標註形式為**多標籤**。少於 20 字者不標。一個單位常包含整個三段論，請把每一步都標出來。

## 二、通用規則

### 規則 1：很多段落不含論證，但不是大多數

論點單位比 400 字段落長，NONE 的比例預期會比 v0.3、v0.4（約 38.5%）低。
**若 NONE 比例明顯高於 40%，請回頭檢查 PROC、UNC、RULE、CONCL 是否漏標。**

### 規則 2：只標本院自己的論理

| 內容 | 標不標 |
|---|---|
| 「上訴意旨略以⋯⋯」「被告則以⋯⋯」轉述當事人主張 | NONE |
| 「證人甲證稱⋯⋯」單純轉述證詞 | NONE |
| 轉述他案的判斷（刑事不起訴處分書、前案判決的認定）而本院未表示採用 | NONE |
| 「惟查，原審已斟酌⋯⋯」法院對上述內容的評價 | 標 |

### 規則 3：每個標籤都要有原文依據（v0.6 修訂）

每標一個標籤，必須逐字引用原文。**引不出來就不得標。**

| 長度 | 寫法 | 例 |
|---|---|---|
| 100 字以內 | 整段逐字引用（至少 10 字），可以從句子中間開始 | 「為有理由，應予准許」 |
| 超過 100 字 | 只寫**開頭 8–30 字**與**結尾 8–30 字**，中間以「〔略〕」代替，開頭、結尾都逐字照抄 | 「原告依消費借貸之法律關係，請求被告〔略〕按週年利率5%計算之利息，為有理由，應予准許」 |

- 引文必須包含完成該動作的用語（規則 10）；用〔略〕時，**這個用語必須寫在結尾**。
- 句子太長時，**從結論往前取**，不要從句首開始引到一半就停（v0.5 的 CONCL 長請求句就是這樣被截斷的）。

**程式怎麼還原完整範圍**（`annotate.resolve_quote`）：

1. 先整段比對。原文本來就有省略號的引文，在這一步就會找到。
2. 找不到、而且有一個〔略〕，才切成開頭、結尾：**先找結尾，再往回找最靠近的開頭**，切出最短的範圍，避免把兩個請求混在一起。
3. 不合法的情形：開頭不到 8 字、結尾不到 4 字、有兩個以上〔略〕、範圍超過上限（400 字；RULE 800 字）。

**上限的依據**（v0.6 試標 290 單位 × 3 次，共 3,177 筆標註、458 筆用〔略〕）：RULE 以外的標籤，還原的範圍最長 385 字；
RULE 一次陳述好幾條法條時常到 400–600 字，屬於正常寫法；1,000 字以上的是把整個單位框起來，仍算不合法。
結尾常是「並不可採」「核定相當之數額」這類 4–7 字的短結論，所以結尾下限設 4 字；開頭是往回找的，維持 8 字以免對到別處。
這是看過試標資料才訂的格式規則，只影響「引文能不能還原」，不影響標籤正確率；引文對不對仍由人工抽查判斷。
規則調整後，用 `python -m annotation.annotate --reparse` 依新規則重新判定所有引文（不呼叫 API）。

資料庫的 `quote` 欄存模型原本寫的引文；完整範圍隨時可以用「引文＋單位原文」重新算出來。抽查表另有「完整範圍」欄。

### 規則 4：引文必須完全出自待標段落

不得引用前後文。

### 規則 5：不確定時選 NONE

### 規則 6：前置標題句與收束結論句（v0.5 修訂）

- **前置標題句 → NONE**
- **收束結論句**（「綜上」「是以」「從而」）：句中重述理由者標該理由的類型；**只宣告請求有無理由者 → CONCL**（v0.4 以前是 NONE）

### 規則 7：刑民分流

### 規則 8：法條的兩種寫法

| 寫法 | 例 | 標籤 |
|---|---|---|
| **判決依據的條號清單** | 「據上論結，依民事訴訟法第 78 條、第 385 條第 1 項前段，判決如主文」 | **NONE** |
| **陳述大前提** | 「按損害之發生或擴大，被害人與有過失者，法院得減輕賠償金額，或免除之」 | **RULE** |

大前提段落同時引用判例者加標 CL；說明舉證責任分配者加標 BOP；說明立法理由者加標 HI。

### 規則 9：固定套語 → NONE

「兩造其餘攻擊或防禦方法及所提證據，經本院斟酌後，認為均不足以影響本判決之結果，爰不逐一論列」標 NONE。

### 規則 10：引文必須包含完成該動作的用語（v0.5 修訂）

| 標籤 | 引文必須包含 | 不能只引 |
|---|---|---|
| EV | 法院的**評價或推論**（堪信、足認、足見、可知、難認、不足採⋯⋯） | 列舉證據的部分 |
| SUB | **定性結論**（核屬、即屬、係犯、構成、不該當⋯⋯） | 大前提或事實敘述 |
| **CONCL** | **請求判斷**（為有理由、應予准許、應予駁回、於法有據⋯⋯） | 請求的內容 |
| RULE | 規範的**內容** | 只有條號 |
| DAM | **決定金額**的句子 | 單純列出請求項目 |
| PROC | **程序處分** | 只陳述程序法條（那是 RULE） |

**例**

> 原告主張之事實，業據提出與其所述相符之授信約定書、連帶保證書、借據⋯⋯等件為證，**堪信原告之主張為真實**。

- ✗ 引文：「業據提出與其所述相符之授信約定書、連帶保證書、借據」（列舉證據）
- ✓ 引文：「借據⋯⋯等件為證，堪信原告之主張為真實」（v0.5 可以從句中開始，只要包含評價）

程式會自動檢查引文是否含動作用語（`cues.py` 的 `QUOTE_ACT`），只用來篩出可疑的列。

### 規則 11：看起來像、但不是（v0.6 修訂）

| 句型 | 看起來像 | 實際上 |
|---|---|---|
| (A)「有⋯⋯在卷可稽／可佐」「業據提出⋯⋯為證」而**沒有**評價 | EV | 只是列舉證據 |
| (B) **抽象規則或假設句**：「倘」「如」「若」，或主詞不是本案當事人 | SUB | **RULE** |
| (C) 讓步句：「姑不論」「縱認」「退步言」 | SUB、EV | 法院**沒有**採為結論 → 不標 |
| (D) **轉述他案判決**的認定 | SUB、EV、CL | **NONE**；本院引用他案判決的**法律見解**作為依據才是 CL |
| (E) 駁斥一方的**法律主張**（「被告辯稱該契約不生效力，洵無可採」）（v0.5 新增） | EV | 爭的是法律效果，不是事實 → 依內容標 SUB 或 RULE |
| (F) 引用程序法條並**在本案做出處分**（「本件⋯⋯依同法第 389 條第 1 項第 3 款規定，應依職權宣告假執行」「顯係為延滯訴訟而提出，應予駁回」）（v0.6 新增） | RULE、SUB | **只標 PROC** |
| (G) 主詞是**抽象的人或情形**（「如未能證明蓋用印文之印章係真正，自無討論⋯⋯之必要」）（v0.6 新增） | SUB | **RULE** |

### 規則 12：同一個標籤可以有多段引文（v0.5 新增）

一個論點單位可能有兩個爭點，各自有 EV、CONCL。同一個標籤出現多次，各列一筆，各附引文。
例：本金的請求有理由、利息的請求一部有理由 → 兩筆 CONCL，方向分別是「有理由」「一部有理由」。

## 三、決策流程

```
步驟一：這段有沒有本院自己的動作？
        ├─ 純粹轉述當事人主張、證詞或他案判斷 → NONE
        ├─ 前置標題句 → NONE
        ├─ 判決依據的條號清單（規則 8） → NONE
        ├─ 固定套語（規則 9） → NONE
        └─ 有 → 步驟二

步驟二：用一兩句話說出法院在本段依序完成了哪些動作（輸出的 analysis 欄位）

步驟三：依三段論逐一判斷（可同時多標）
        ├─ 陳述規範或其解釋 → RULE
        ├─ 證據 → 事實（評價證據、依證據推論） → EV
        ├─ 不爭執／視同自認的事實 → UNC
        ├─ 事實 → 法律要件（定性） → SUB
        ├─ 對請求下結論 → CONCL（填方向）
        └─ 已成立的責任 → 刑度或金額 → SENT／DAM

步驟四：逐一檢視其餘標籤（PROC、CL、BOP、HI、EXP、EQUITY、EXO）

步驟五：每個標籤的引文都必須包含完成該動作的用語（規則 10）

步驟六：EV 填傾向與 basis；DAM 填方向；CONCL 填方向；其他標籤留白
```

## 四、刑事標籤（10 類）

刑事標籤集與 v0.4 相同（RULE、SUB、SENT、EV、CL、PROC、HI、ADM、UNC、EXP + NONE），
但 RULE、SUB、EV、EXP 的 v0.5 修訂同樣適用。刑事目前不加 CONCL：論罪的結論本身就是 SUB。

SENT、CL、PROC、HI、ADM、UNC 的定義同 v0.4。

## 五、民事標籤（13 類）

RULE、SUB、CONCL、EV、DAM、CL、UNC、PROC、BOP、HI、EXP、EQUITY、EXO + NONE。

### RULE 規範陳述（刑民共用）

**定義**：法院陳述法律規範的內容或其解釋，作為之後判斷的大前提。

**標**：「按⋯⋯」引述法條內容；「所謂⋯⋯係指⋯⋯」解釋法律概念；
**抽象規則**（主詞不是本案當事人）；**假設句**（「倘」「如」「若」開頭）；一般性的法律見解。

**不標**：只有條號（規則 8，NONE）；**轉述他案判決**的認定（NONE）。

**vs PROC**：陳述程序法的規範是 RULE；法院在本案實際做出程序處分才是 PROC。

### SUB 涵攝（定性）（v0.6 修訂）

**定義**：法院把本案事實套入法律要件，**完成**該當或不該當的定性。推論方向是「事實 → 法律要件」。

**v0.5：SUB 只收定性。** 對請求有沒有理由的結論改標 CONCL。

**常見寫法**：「核被告所為，係犯⋯⋯罪」、核屬／即屬／自屬／應屬 + 法律概念（「核屬給付型不當得利」）、構成⋯⋯、該當／不該當⋯⋯要件。

**v0.5 新增的判準**：

| 句型 | 標籤 |
|---|---|
| 「堪認／足認」後面接**事實**（「堪認被告確有收受該款項」） | EV |
| 「堪認／足認」後面接**法律評價**（「堪認被告有過失」「足認兩造間成立借名登記契約」） | **SUB** |
| 「送達」用來認定**意思表示已到達**（解除契約、催告、抵銷） | **SUB**（不是 PROC） |
| 「為有理由」「應予准許」「即屬有據」「核屬有理」 | **CONCL**（不是 SUB） |

**v0.6 新增的判準**：

| 情形 | 標籤 | 例 |
|---|---|---|
| 先看主詞：主詞抽象（「行為人」「如未能證明⋯⋯」） | **RULE** | 3279 |
| 只認定「什麼時候、以什麼名義」發生了什麼事，沒有判斷要件 | **EV／UNC** | 3286 |
| 程序法條在本案的適用 | **PROC**（規則 11F） | 3093、3234 |
| 舉證責任的分配、證據力的判斷 | **BOP／EV** | 3279 |
| 「自得請求」「得請求被告給付」：定性的法律效果 | **SUB**（不是 CONCL） | 3241 |
| 過失相抵、與有過失的抗辯**在要件階段就不成立**（「尚無過失相抵法則適用之餘地」） | **SUB**（不是 DAM） | DAM 3202、3230 |

**不標**：只有大前提（RULE）；讓步句與他案判斷（規則 11）；事實可不可信（EV）。

### CONCL 請求判斷（v0.5 新增，民事）

**定義**：法院對某項請求（訴之聲明、反訴、上訴、追加之訴）下的結論：有沒有理由、准不准許。

**常見寫法**：為有理由、為無理由、一部有理由、應予准許、不應准許、應予駁回、即屬有據、洵屬有據、自屬有據、於法有據、即無不合、核屬有理。

**方向欄位**（必填）。v0.6：方向依「**本段寫出的判斷**」：本段只寫准許的範圍、沒寫駁回 → 有理由；本段同時寫准許與駁回 → 一部有理由。不用推測整件判決的勝敗（CONCL 3122）。

**不是 CONCL**：對「抗辯」的判斷（「被告之時效抗辯為有理由」，RULE 3198）；「自得請求」（SUB）；假執行聲請的駁回（PROC，3139）。

| 方向 | 意思 | 例 |
|---|---|---|
| 有理由 | 該請求全部准許 | 「原告請求被告給付 50 萬元及法定遲延利息，為有理由，應予准許」 |
| 一部有理由 | 准許一部分、駁回一部分 | 「於 20 萬元之範圍內為有理由，應予准許；逾此部分之請求，為無理由，應予駁回」 |
| 無理由 | 該請求全部駁回 | 「原告之請求，為無理由，應予駁回」 |

**注意**：

- 同一段兩個請求、方向不同 → 各列一筆（規則 12）
- **程序上駁回**（起訴不合法）→ PROC，不是 CONCL
- 「核無不合」用在假執行擔保時是 PROC；用在請求時是 CONCL
- 同一段若也寫了理由，理由另外標 EV／SUB／DAM

**和判決結果比對**（`spot_check.py`，程式自動檢查，結果寫在抽查表「判決結果比對」欄）：

| 判決結果（`cases.outcome`） | CONCL 方向 | 標記 |
|---|---|---|
| 敗訴 | 有理由、一部有理由 | **衝突** |
| 勝訴、確認勝訴 | 無理由、一部有理由 | **注意** |
| 一部勝訴一部敗訴 | 任何方向 | 一致 |

這只是提示：判決結果是案件層級，「有理由」也可能是反訴、上訴或追加之訴的結論，要人工看原文確認。

### EV 證據評價（v0.6 修訂）

**定義**：法院就特定證據**表示採信或不採信**，或**依證據推論**出事實。推論方向是「證據 → 事實」。

**v0.6 判準：必須有被評價的具體證據**（證人證詞、書證、鑑定、錄音、勘驗、照片、函文⋯⋯）。只有評價的語氣、沒有證據，就不是 EV：

| 情形 | 標籤 | 例（v0.5 抽查） |
|---|---|---|
| 當事人沒提出證據，所以不採信其主張（「被告就其抗辯並未提出證據以實其說，本院尚無法採信」） | **BOP** | 3022 |
| 從不爭執的事實或已認定的事實，推到法律要件 | **SUB** | 3101、SUB 3248 |
| 依當事人的陳述或訴訟過程推論，沒有被評價的證據 | **不標 EV** | 3112、3126 |
| 解釋契約條款 | **SUB** | 3155 |
| 「堪信原告受有精神痛苦」：有診斷證明、證詞等證據 | EV | SUB 3215 |
| 同上，但沒有證據、是慰撫金審酌的一部分 | 併入 **DAM** | SUB 3215 |
| 指明卷證、實際評價證據的「舉證不足」 | **EV＋BOP** | 3088 |

「可知、可見、足見、足徵」**前面要指明證據**才是 EV（依證據推論）；只承接已認定的事實 → 併入 SUB。

**評價用語**：

| 類別 | 用語 |
|---|---|
| 採信 | 堪信、可採、足認、堪認、應堪認定、核與⋯⋯相符、**吻合**、互核一致、非虛、**屬實**、可資佐證、足見、益徵、顯見、足證、經勘驗屬實 |
| **依證據推論**（v0.5） | **可知、可見、足徵**（「由上開函文可知，被告已於 112 年 5 月間收受該通知」） |
| 不採信 | 不足採、**無足採**、無可採、不可採、難認、尚難、無足取、顯有疑義、難以採信、前後不一 |
| 證明不足 | 尚無法證明、不能證明、**難證明**、**無從⋯⋯認定**、查無其他積極證據 |

**子欄位 `basis`**（v0.5 新增，存在 `annotations.subtype`）：

| basis | 意思 | 典型用語 |
|---|---|---|
| 明示評價 | 法院直接說證據可不可信 | 堪信、可採、不足採、相符 |
| 依證據推論 | 法院從證據推出另一個事實 | 可知、可見、足徵、足見 |

**不標 EV**：

- 只列舉卷證而沒有評價（規則 11A）
- 依「不爭執」「視同自認」而「堪信為真實」→ **UNC**
- 駁斥一方的法律主張（規則 11E）
- 「堪認／足認」後接法律評價 → SUB

**屬性欄位**：`傾向 = 有利原告／有利被告／中性`

### UNC 不爭執事項（v0.5 修訂）

兩造不爭執、爭點整理的不爭執事項、自認、視同自認、顯著事實。

**v0.5 的 EV／UNC 界線**：

| 情形 | 標籤 |
|---|---|
| 「被告對原告主張之事實不爭執，堪信為真實」 | **UNC** |
| 「被告經合法通知未到場，亦未提出書狀爭執，依民事訴訟法第 280 條第 3 項視同自認，堪信原告之主張為真實」 | **UNC** |
| 被告受公示送達未到場，但法院**逐一檢視**原告提出的證據後才認定（抽查 2025） | **EV** |

判準：法院是因為「沒有爭執」而採信（UNC），還是實際**衡量了證據**（EV）？

### PROC 程序處理（v0.6 修訂）

| 情形 | 例 |
|---|---|
| 訴訟要件、當事人適格、管轄、確認利益 | 「本件原告各項確認之訴，俱有確認利益」 |
| 起訴不合法、程序上駁回 | |
| 訴之聲明的記載與處理 | |
| 裁判費的徵收或免徵 | |
| 一事不再理、既判力 | |
| 審級程序的限制 | |
| **一造辯論的程序效果** → **同時標 PROC 和 UNC**（v0.5） | 「被告經合法通知，未於言詞辯論期日到場，核無民事訴訟法第 386 條所列各款情形，爰依原告之聲請，由其一造辯論而為判決」 |
| 訴訟文書送達之合法與生效 | 寄存送達、公示送達之生效日 |
| 假執行之宣告與擔保 | 「原告陳明願供擔保請准宣告假執行，核無不合，爰酌定相當之擔保金額准許之」 |

| 駁回逾時提出的攻擊防禦方法（民訴第 196 條第 2 項）（v0.6） | 「顯係為延滯訴訟而提出，有礙訴訟終結，應予駁回」 |
| 認諾判決、訴訟費用的負擔與確定（v0.6） | 「本院酌量本件訴訟係肇因於被告未依約履行而生，故命由被告一造負擔訴訟費用」 |

**v0.6：引用程序法條並做出處分時，只標 PROC，不另標 RULE 或 SUB**（規則 11F）。主詞是「本件」、或句子做出了處分 → PROC；只陳述程序法條的內容 → RULE。

**送達**：法院判斷送達何時生效（「自同年 5 月 8 日生送達效力」）→ PROC；只寫「自起訴狀繕本送達翌日起」算利息 → 不標（PROC 3107）。

**不標**：只陳述程序法的規範內容（RULE）；利息起算日的「送達」；**以送達認定意思表示到達**（SUB）；訴訟費用負擔依據的條號清單（規則 8）。

### HI 歷史解釋（v0.5 民事新增）

**定義**：援引立法理由、修法沿革、立法者意旨解釋法律；新舊法比較、法律不溯及既往、民法施行法的適用。

**標**：「立法理由謂⋯⋯」「修正理由」「舊法第⋯⋯條規定」「依民法債編施行法第⋯⋯條」。

### EXP 經驗論理法則（v0.6 修訂：開放的功能定義）

**定義**：法院以**一般經驗、常情、社會通念或論理**作為判斷的依據。看功能，**不限特定用語**。

**為什麼改**：v0.5 用逐字封閉清單，抽查只有 10/25。錯誤幾乎都是清單用語的同義變化，連清單本來就有的詞的小變化
（3285「衡諸社會通念」、3280「依一般社會通常觀念」）都被判錯。用語的寫法太多，逐字清單行不通。

**常見寫法**（舉例，不是清單）：

| 家族 | 例 |
|---|---|
| 常情 | 衡情、依常情、衡諸常情、悖於常情、顯悖常情、與借款常情不合、尚與常情相合、亦無違於常情、符合社會常情 |
| 社會通念 | 依社會通念、衡諸社會通念、依一般社會通常觀念 |
| 經驗、論理法則 | 經驗法則、論理法則、依一般經驗、事理之常 |
| 一般人的認知、普遍現象 | 一般人均知、眾所周知、屢見不鮮、實務上並非罕見、「一般男女交往常會⋯⋯」 |
| 證明度標準 | 「通常一般之人均不致有所懷疑」 |

**不標**：一般知識或顯著事實本身（「一般農業機具寬度約 2 公尺至 4 公尺不等」，3189）→ UNC；只有「通常」兩字而沒有拿來當判斷依據。

**抽查時看兩件事**：是不是這個功能的變化型；有沒有明顯完全不是在講經驗法則的錯誤。

### DAM 給付額酌定（v0.6 修訂）

定義同 v0.4，方向欄位：`酌減／全額准許／不明`。

**v0.6 判準：法院必須實際進行金額的裁量。**

| 情形 | 法院做了什麼 | 標籤 |
|---|---|---|
| 慰撫金審酌後全額准許 | 實際斟酌身分、地位、痛苦程度，裁量後認為請求的金額適當 | DAM（全額准許） |
| 過失相抵的抗辯被駁回（DAM 3202、3230，RULE 3098） | 要件不成立，沒有進入減免金額的裁量 | **SUB**（要件不該當） |
| 被告同意的金額（SUB 3237）、被告不爭執的金額（SUB 3247）、依法定公式計算（資遣費，RULE 3086） | 沒有裁量 | 不標 DAM |

### BOP 舉證責任（v0.6 補充）

除民事訴訟法第 277 條、「應由原告負舉證之責」、「未能舉證」、事實真偽不明外，補上：**「舉證不足」**、
**當事人沒有提出證據、法院因此不採其主張**（「未提出證據以實其說」，EV 3022）。

### CL 判例援引、EQUITY 法律原則、EXO 職權調查

定義同 v0.4。

## 八、已知限制

1. **修訂未經法律專業人員審閱。** CONCL、EV／SUB／UNC／BOP 的界線與 EXP 的功能定義，由非法律背景的研究者依抽查結果決定。
2. **抽查只能估精確度，不能估召回率。** 漏標（例如 v0.4 的一造辯論漏 PROC）只能從抽查時順便發現。
3. **法律專業的驗證只來自一位法律系學生，共 77 段。**
4. **標註單位和判決導讀的段落不同。** 論點單位（最多 1,200 字）不等於 `civil/insights.py` 的 400 字段落；
   要接上導讀，需用 `unit_start` 加上引文在單位內的位置，對回導讀段落。是否改用論點單位，尚待組員確認。
5. **仍有 32% 的論點，大前提和結論不在同一單位。** 分析時以（案件, 單位序號）把相鄰單位接回。
6. **CONCL 和判決結果的比對是案件層級。** 有反訴、多個請求或上訴的判決，「衝突」不一定是標錯。
7. **EXP 改成功能定義後，判斷比封閉清單主觀。** 抽查時以「是不是同一功能的變化型」判斷；v0.5 照封閉清單的 10/25 不能和 v0.6 直接比較。
8. **RULE 尚未細分解釋方法。** 文義、體系、目的解釋目前都標 RULE。
9. **語料偏斜。** 民事為組內資料庫（一審、對審），刑事以二審為主。
10. **引文格式改變（〔略〕）。** v0.6 的引文正確率以還原後的完整範圍判斷，不能和 v0.5 直接比較。
