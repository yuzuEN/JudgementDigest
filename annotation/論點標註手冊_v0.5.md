# 台灣判決書論點標註手冊 v0.5

標註判決理由中「法院在做什麼」的規則。以 AI 為主要標註者，人工依線索抽查。

## v0.5 的修訂摘要

v0.4 的 RULE、PROC、DAM 抽查全部符合，EV、SUB 各為 19/24（0.79）。v0.5 處理三件事：
**請求判斷從 SUB 分出來（CONCL）**、**釐清 EV／SUB／UNC 的界線**、**標註單位改成論點單位**。

| 項目 | v0.4 | v0.5 | 依據 |
|---|---|---|---|
| **CONCL 請求判斷**（民事） | 「為有理由」「應予准許」混在 SUB 或只宣告結果的 NONE | **新增**，附方向：有理由／一部有理由／無理由 | SUB 只收定性；CONCL 可給 D3 使用，也能和判決結果自動比對 |
| SUB | 本段完成定性 | **只收定性**；「堪認／足認」後接法律評價者歸 SUB；以送達認定意思表示到達歸 SUB | v0.4 SUB 抽查 19/24 |
| EV | 明示評價 | 納入**依證據推論**（可知、可見、足徵）；新增子欄位 `basis` | v0.4 EV 抽查 19/24 |
| EV／UNC 界線 | — | 依「不爭執／視同自認」而「堪信」→ UNC；有實際衡量證據才標 EV | 抽查 2025（公示送達案） |
| EV 的範圍 | — | 駁斥一方的**法律主張**（「無可採」）不是 EV | v0.4 EV 抽查 |
| **EXP** | 明示援引（開放） | **封閉清單**；一般經驗陳述也標 EXP | 清單外的判斷不穩定 |
| 一造辯論 | PROC | **同時標 PROC 和 UNC** | 模型漏標 PROC 7 次（只標 UNC） |
| **HI**（民事） | 只有刑事 | 民事加入 | 民事沒有 HI 標籤可用 |
| 規則 11 | 四種誤導句型 | 寫清楚：抽象規則和假設句 → RULE；**轉述他案判決 → NONE**；新增 (E) 駁斥法律主張 | — |
| 規則 3（引文） | 10–60 字 | **10–100 字**，可從句中開始，但必須包含完成該動作的用語 | 單位變長，完整的動作句常超過 60 字 |
| 規則 12（新增） | 一個標籤一段引文 | **同一個標籤可以有多段引文** | 一個單位可能有兩個爭點 |
| **標註單位** | 組員的 400 字段落 | **論點單位**（依編號層級切，最多 1,200 字） | 見第一節 |

**未改動的標籤**：CL、BOP、ADM、EQUITY、EXO、SENT、DAM 的定義與 v0.4 相同（DAM 的方向欄不變）。

## 一、研究目的與標註單位

### 研究目的

分析不同法官在認定事實、評價證據、建立法律前提、量定刑度與賠償金額時的傾向差異；
標註結果同時供平台的判決導讀使用。

遇到邊界模糊時，回到這個問題判斷：**這段文字能不能告訴我們這位法官重視什麼？**

### 法律依據

| 規定 | 對應標籤 |
|---|---|
| 民訴§222 Ⅰ 證據力評價之自由 | EV 證據評價 |
| 民訴§222 Ⅱ 損害額之酌定 | DAM 給付額酌定 |
| 民訴§222 Ⅲ 經驗法則或論理法則 | EXP 經驗論理法則 |
| 證據能力有無 | ADM 證據能力（刑事） |

### 法學三段論與標籤的對應

| 步驟 | 法院在做什麼 | 標籤 |
|---|---|---|
| 大前提 | 陳述法律規範或其解釋 | **RULE** |
| 小前提 | 由證據認定事實 | **EV**（或 UNC：不爭執的事實） |
| 定性 | 把事實套入法律要件，得出該當與否 | **SUB** |
| 請求判斷（v0.5） | 對請求下結論：有理由／無理由 | **CONCL**（民事） |
| 法律效果的裁量 | 決定刑度或金額 | **SENT**（刑事）／**DAM**（民事） |

**CONCL 不算法官分析的一部分。** 它記錄的是判斷的結果，不是論證的理由：
分析法官論理傾向時排除 CONCL；CONCL 用在 D3，以及和判決結果自動比對。

### 標註單位（v0.5 修訂）

| | 範圍 | 切分方式 |
|---|---|---|
| **民事** | 組內資料庫 `sections.court`（法院判斷段） | **論點單位**：`annotation/structure.py` 的 `units(text, 1200)` |
| **刑事** | 理由全文 | 切段規則 v2；待刑事組的段落結構確定後再統一 |

**論點單位怎麼切**：依判決的編號層級（壹、→ 一、→ ㈠／(一) → ⒈／1. → ⑴／(1) → ①）解析成樹。
由上往下，一個節點（含所有子項）在 1,200 字內就整塊當一個單位；太長才拆成下一層；
沒有子編號又太長，才在句號處切。編號要通過位置與順序檢查，避免把「第一、二審」「1.5萬元」當成編號。

**3,000 件判決的測試結果**：

| | 組員的 400 字段落 | 論點單位（N=1,200） |
|---|---|---|
| 解析得出編號的判決 | — | 99.8% |
| 每件平均單位數 | — | 6.3 |
| 單位長度中位數 | — | 281 字 |
| 要在句號處硬切的單位 | — | 4.6% |
| 同一論點的大前提和結論落在同一單位 | 46.9% | **68%** |

**前後文**：只給相鄰單位的 300 字（前一單位的最後 300 字、後一單位的前 300 字），只用來理解脈絡。

標註形式為**多標籤**。少於 20 字者不標。一個單位常包含整個三段論，請把每一步都標出來。

## 二、通用規則

### 規則 1：很多段落不含論證，但不是大多數

論點單位比 400 字段落長，NONE 的比例預期會比 v0.3、v0.4（約 38.5%）低。
**若 NONE 比例明顯高於 40%，請回頭檢查 PROC、UNC、RULE、CONCL 是否漏標。**

### 規則 2：只標本院自己的論理

| 內容 | 標不標 |
|---|---|
| 「上訴意旨略以⋯⋯」「被告則以⋯⋯」轉述當事人主張 | NONE |
| 「證人甲證稱⋯⋯」單純轉述證詞 | NONE |
| 轉述他案的判斷（刑事不起訴處分書、前案判決的認定）而本院未表示採用 | NONE |
| 「惟查，原審已斟酌⋯⋯」法院對上述內容的評價 | 標 |

### 規則 3：每個標籤都要有原文依據（v0.5 修訂）

每標一個標籤，必須引用 **10 至 100 字**的原文。**引不出來就不得標。**
引文可以**從句子中間開始**，但必須包含完成該動作的用語（規則 10）。

### 規則 4：引文必須完全出自待標段落

不得引用前後文。

### 規則 5：不確定時選 NONE

### 規則 6：前置標題句與收束結論句（v0.5 修訂）

- **前置標題句 → NONE**
- **收束結論句**（「綜上」「是以」「從而」）：句中重述理由者標該理由的類型；**只宣告請求有無理由者 → CONCL**（v0.4 以前是 NONE）

### 規則 7：刑民分流

### 規則 8：法條的兩種寫法

| 寫法 | 例 | 標籤 |
|---|---|---|
| **判決依據的條號清單** | 「據上論結，依民事訴訟法第 78 條、第 385 條第 1 項前段，判決如主文」 | **NONE** |
| **陳述大前提** | 「按損害之發生或擴大，被害人與有過失者，法院得減輕賠償金額，或免除之」 | **RULE** |

大前提段落同時引用判例者加標 CL；說明舉證責任分配者加標 BOP；說明立法理由者加標 HI。

### 規則 9：固定套語 → NONE

「兩造其餘攻擊或防禦方法及所提證據，經本院斟酌後，認為均不足以影響本判決之結果，爰不逐一論列」標 NONE。

### 規則 10：引文必須包含完成該動作的用語（v0.5 修訂）

| 標籤 | 引文必須包含 | 不能只引 |
|---|---|---|
| EV | 法院的**評價或推論**（堪信、足認、足見、可知、難認、不足採⋯⋯） | 列舉證據的部分 |
| SUB | **定性結論**（核屬、即屬、係犯、構成、不該當⋯⋯） | 大前提或事實敘述 |
| **CONCL** | **請求判斷**（為有理由、應予准許、應予駁回、於法有據⋯⋯） | 請求的內容 |
| RULE | 規範的**內容** | 只有條號 |
| DAM | **決定金額**的句子 | 單純列出請求項目 |
| PROC | **程序處分** | 只陳述程序法條（那是 RULE） |

**例**

> 原告主張之事實，業據提出與其所述相符之授信約定書、連帶保證書、借據⋯⋯等件為證，**堪信原告之主張為真實**。

- ✗ 引文：「業據提出與其所述相符之授信約定書、連帶保證書、借據」（列舉證據）
- ✓ 引文：「借據⋯⋯等件為證，堪信原告之主張為真實」（v0.5 可以從句中開始，只要包含評價）

程式會自動檢查引文是否含動作用語（`cues.py` 的 `QUOTE_ACT`），只用來篩出可疑的列。

### 規則 11：看起來像、但不是（v0.5 修訂）

| 句型 | 看起來像 | 實際上 |
|---|---|---|
| (A)「有⋯⋯在卷可稽／可佐」「業據提出⋯⋯為證」而**沒有**評價 | EV | 只是列舉證據 |
| (B) **抽象規則或假設句**：「倘」「如」「若」，或主詞不是本案當事人 | SUB | **RULE** |
| (C) 讓步句：「姑不論」「縱認」「退步言」 | SUB、EV | 法院**沒有**採為結論 → 不標 |
| (D) **轉述他案判決**的認定 | SUB、EV、CL | **NONE**；本院引用他案判決的**法律見解**作為依據才是 CL |
| (E) 駁斥一方的**法律主張**（「被告辯稱該契約不生效力，洵無可採」）（v0.5 新增） | EV | 爭的是法律效果，不是事實 → 依內容標 SUB 或 RULE |

### 規則 12：同一個標籤可以有多段引文（v0.5 新增）

一個論點單位可能有兩個爭點，各自有 EV、CONCL。同一個標籤出現多次，各列一筆，各附引文。
例：本金的請求有理由、利息的請求一部有理由 → 兩筆 CONCL，方向分別是「有理由」「一部有理由」。

## 三、決策流程

```
步驟一：這段有沒有本院自己的動作？
        ├─ 純粹轉述當事人主張、證詞或他案判斷 → NONE
        ├─ 前置標題句 → NONE
        ├─ 判決依據的條號清單（規則 8） → NONE
        ├─ 固定套語（規則 9） → NONE
        └─ 有 → 步驟二

步驟二：用一兩句話說出法院在本段依序完成了哪些動作（輸出的 analysis 欄位）

步驟三：依三段論逐一判斷（可同時多標）
        ├─ 陳述規範或其解釋 → RULE
        ├─ 證據 → 事實（評價證據、依證據推論） → EV
        ├─ 不爭執／視同自認的事實 → UNC
        ├─ 事實 → 法律要件（定性） → SUB
        ├─ 對請求下結論 → CONCL（填方向）
        └─ 已成立的責任 → 刑度或金額 → SENT／DAM

步驟四：逐一檢視其餘標籤（PROC、CL、BOP、HI、EXP、EQUITY、EXO）

步驟五：每個標籤的引文都必須包含完成該動作的用語（規則 10）

步驟六：EV 填傾向與 basis；DAM 填方向；CONCL 填方向；其他標籤留白
```

## 四、刑事標籤（10 類）

刑事標籤集與 v0.4 相同（RULE、SUB、SENT、EV、CL、PROC、HI、ADM、UNC、EXP + NONE），
但 RULE、SUB、EV、EXP 的 v0.5 修訂同樣適用。刑事目前不加 CONCL：論罪的結論本身就是 SUB。

SENT、CL、PROC、HI、ADM、UNC 的定義同 v0.4。

## 五、民事標籤（13 類）

RULE、SUB、CONCL、EV、DAM、CL、UNC、PROC、BOP、HI、EXP、EQUITY、EXO + NONE。

### RULE 規範陳述（刑民共用）

**定義**：法院陳述法律規範的內容或其解釋，作為之後判斷的大前提。

**標**：「按⋯⋯」引述法條內容；「所謂⋯⋯係指⋯⋯」解釋法律概念；
**抽象規則**（主詞不是本案當事人）；**假設句**（「倘」「如」「若」開頭）；一般性的法律見解。

**不標**：只有條號（規則 8，NONE）；**轉述他案判決**的認定（NONE）。

**vs PROC**：陳述程序法的規範是 RULE；法院在本案實際做出程序處分才是 PROC。

### SUB 涵攝（定性）（v0.5 修訂）

**定義**：法院把本案事實套入法律要件，**完成**該當或不該當的定性。推論方向是「事實 → 法律要件」。

**v0.5：SUB 只收定性。** 對請求有沒有理由的結論改標 CONCL。

**常見寫法**：「核被告所為，係犯⋯⋯罪」、核屬／即屬／自屬／應屬 + 法律概念（「核屬給付型不當得利」）、構成⋯⋯、該當／不該當⋯⋯要件。

**v0.5 新增的判準**：

| 句型 | 標籤 |
|---|---|
| 「堪認／足認」後面接**事實**（「堪認被告確有收受該款項」） | EV |
| 「堪認／足認」後面接**法律評價**（「堪認被告有過失」「足認兩造間成立借名登記契約」） | **SUB** |
| 「送達」用來認定**意思表示已到達**（解除契約、催告、抵銷） | **SUB**（不是 PROC） |
| 「為有理由」「應予准許」「即屬有據」「核屬有理」 | **CONCL**（不是 SUB） |

**不標**：只有大前提（RULE）；讓步句與他案判斷（規則 11）；事實可不可信（EV）。

### CONCL 請求判斷（v0.5 新增，民事）

**定義**：法院對某項請求（訴之聲明、反訴、上訴、追加之訴）下的結論：有沒有理由、准不准許。

**常見寫法**：為有理由、為無理由、一部有理由、應予准許、不應准許、應予駁回、即屬有據、洵屬有據、自屬有據、於法有據、即無不合、核屬有理。

**方向欄位**（必填）：

| 方向 | 意思 | 例 |
|---|---|---|
| 有理由 | 該請求全部准許 | 「原告請求被告給付 50 萬元及法定遲延利息，為有理由，應予准許」 |
| 一部有理由 | 准許一部分、駁回一部分 | 「於 20 萬元之範圍內為有理由，應予准許；逾此部分之請求，為無理由，應予駁回」 |
| 無理由 | 該請求全部駁回 | 「原告之請求，為無理由，應予駁回」 |

**注意**：

- 同一段兩個請求、方向不同 → 各列一筆（規則 12）
- **程序上駁回**（起訴不合法）→ PROC，不是 CONCL
- 「核無不合」用在假執行擔保時是 PROC；用在請求時是 CONCL
- 同一段若也寫了理由，理由另外標 EV／SUB／DAM

**和判決結果比對**（`spot_check.py`，程式自動檢查，結果寫在抽查表「判決結果比對」欄）：

| 判決結果（`cases.outcome`） | CONCL 方向 | 標記 |
|---|---|---|
| 敗訴 | 有理由、一部有理由 | **衝突** |
| 勝訴、確認勝訴 | 無理由、一部有理由 | **注意** |
| 一部勝訴一部敗訴 | 任何方向 | 一致 |

這只是提示：判決結果是案件層級，「有理由」也可能是反訴、上訴或追加之訴的結論，要人工看原文確認。

### EV 證據評價（v0.5 修訂）

**定義**：法院就特定證據**表示採信或不採信**，或**依證據推論**出事實。推論方向是「證據 → 事實」。

**評價用語**：

| 類別 | 用語 |
|---|---|
| 採信 | 堪信、可採、足認、堪認、應堪認定、核與⋯⋯相符、**吻合**、互核一致、非虛、**屬實**、可資佐證、足見、益徵、顯見、足證、經勘驗屬實 |
| **依證據推論**（v0.5） | **可知、可見、足徵**（「由上開函文可知，被告已於 112 年 5 月間收受該通知」） |
| 不採信 | 不足採、**無足採**、無可採、不可採、難認、尚難、無足取、顯有疑義、難以採信、前後不一 |
| 證明不足 | 尚無法證明、不能證明、**難證明**、**無從⋯⋯認定**、查無其他積極證據 |

**子欄位 `basis`**（v0.5 新增，存在 `annotations.subtype`）：

| basis | 意思 | 典型用語 |
|---|---|---|
| 明示評價 | 法院直接說證據可不可信 | 堪信、可採、不足採、相符 |
| 依證據推論 | 法院從證據推出另一個事實 | 可知、可見、足徵、足見 |

**不標 EV**：

- 只列舉卷證而沒有評價（規則 11A）
- 依「不爭執」「視同自認」而「堪信為真實」→ **UNC**
- 駁斥一方的法律主張（規則 11E）
- 「堪認／足認」後接法律評價 → SUB

**屬性欄位**：`傾向 = 有利原告／有利被告／中性`

### UNC 不爭執事項（v0.5 修訂）

兩造不爭執、爭點整理的不爭執事項、自認、視同自認、顯著事實。

**v0.5 的 EV／UNC 界線**：

| 情形 | 標籤 |
|---|---|
| 「被告對原告主張之事實不爭執，堪信為真實」 | **UNC** |
| 「被告經合法通知未到場，亦未提出書狀爭執，依民事訴訟法第 280 條第 3 項視同自認，堪信原告之主張為真實」 | **UNC** |
| 被告受公示送達未到場，但法院**逐一檢視**原告提出的證據後才認定（抽查 2025） | **EV** |

判準：法院是因為「沒有爭執」而採信（UNC），還是實際**衡量了證據**（EV）？

**定義**：援引立法理由、修法沿革、立法者意旨解釋法律；新舊法比較、法律不溯及既往、民法施行法的適用。

**標**：「立法理由謂⋯⋯」「修正理由」「舊法第⋯⋯條規定」「依民法債編施行法第⋯⋯條」。

### EXP 經驗論理法則（v0.5 修訂：封閉清單）

**定義**：法院援引經驗法則、論理法則，或以一般經驗作為判斷依據。**只看下列清單，清單以外不標**：

經驗法則、論理法則、屢見不鮮、眾所周知、一般人均知、依社會通念（一般社會通念）、衡諸常情、依一般經驗、事理之常；
或明示表述證明度標準（「通常一般之人均不致有所懷疑」）。

v0.5 起，**一般經驗陳述**（「此類詐騙手法屢見不鮮」）只要用了清單內的用語，也標 EXP。

## 七、驗證方式

| 層次 | 做法 | 能證明 |
|---|---|---|
| 沿用 | 定義未改的標籤（CL、BOP、ADM、EQUITY、EXO）沿用先前與法律系學生比對的結果 | 效度 |

## 八、已知限制

1. **修訂未經法律專業人員審閱。** CONCL、EV／SUB／UNC 的界線與 EXP 的封閉清單，由非法律背景的研究者依抽查結果決定。
2. **抽查只能估精確度，不能估召回率。** 漏標（例如 v0.4 的一造辯論漏 PROC）只能從抽查時順便發現。
3. **法律專業的驗證只來自一位法律系學生，共 77 段。**
4. **標註單位和判決導讀的段落不同。** 論點單位（最多 1,200 字）不等於 `civil/insights.py` 的 400 字段落；
   要接上導讀，需用 `unit_start` 加上引文在單位內的位置，對回導讀段落。是否改用論點單位，尚待組員確認。
5. **仍有 32% 的論點，大前提和結論不在同一單位。** 分析時以（案件, 單位序號）把相鄰單位接回。
6. **CONCL 和判決結果的比對是案件層級。** 有反訴、多個請求或上訴的判決，「衝突」不一定是標錯。
7. **EXP 的封閉清單會漏掉清單外的經驗判斷。** 這是刻意的取捨：換取穩定。
8. **RULE 尚未細分解釋方法。** 文義、體系、目的解釋目前都標 RULE。
9. **語料偏斜。** 民事為組內資料庫（一審、對審），刑事以二審為主。
