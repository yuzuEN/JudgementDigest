# retrieval/：相似判決檢索

## 本機抽取刑事單一刑期資料

在專案根目錄執行（僅需 Python 標準函式庫）：

```bash
python3 -m retrieval.sample_criminal \
  --data ../cail_v2_national_2016-2025/cail_v2.jsonl \
  --out ../criminal_sample_2000/cases.jsonl \
  --per-charge 2000
```

每個主要罪名（`accusation` 第一項）最多 2,000 件，判決日期較新者優先，不足則全收；
不是保證每個案件包含的罪名都各有 2,000 件，也不保證總數達到 10～20 萬。
輸出保留完整 CAIL 記錄，另加 `meta.retrieval_source_line` 以追溯原始行號。
同目錄的 `cases.report.json` 記錄排除原因、各罪名符合條件件數與選取件數。
輸出檔存在時拒絕覆寫，不會更動網站資料庫或建立索引。

條件：犯罪事實非空、`criminals` 恰有一個非空姓名、罪名與法條非空，且罪名與法條的
`task_validity` 均為 true；刑期條件滿足下列其一：

- 有效單一刑期：`imprisonment` 有效，並有 `single_prison_sentence` 或
  `single_special_sentence` 標記及對應有效值（包含死刑／無期徒刑）。
- 有效單一拘役：`sentence_kind=拘役`、`term_reason=detention_not_prison`，且拘役天數為正整數，
  有期徒刑月數為零，沒有死刑／無期徒刑標記；此分支不要求 `imprisonment=true`。

若有新版 `reextraction`，以其刑期標記為準，並要求被告狀態為單被告、選取刑期只有一個。
多個無法確定單一刑期的案件、有期徒刑混合拘役、僅罰金案件不會入選。
舊版資料只能依既有標記判定，沒有重新核對全文，也不能由此確認刑期來源是應執行刑或宣告刑。

日後建立索引時，要同樣指定 2,000，避免建索引程式預設再縮減為每罪名 1,500 件：

```bash
python3 -m retrieval.criminal \
  --data ../criminal_sample_2000/cases.jsonl \
  --per-charge 2000 \
  --out artifacts/retrieval_criminal_2000
```

此步需安裝專案依賴；輸出到獨立目錄。建立的資料庫尚未包含全文，需按案件識別資料
另行匯入原文；新案件清單的 row 已變，不能直接複製舊 `full_text` 表。

描述案情，找出最相似的真實判決。民事、刑事共用同一套檢索核心，各自設定建索引的文字、
篩選條件與顯示內容。

| 檔案 | 內容 |
|---|---|
| `engine.py` | 共用核心：字元 1–3 gram TF-IDF、餘弦相似度；建索引、查前 k 件、存檔讀回 |
| `civil.py` | 民事設定：用原告主張建索引（使用者只能提供自己這一方的說法），可限定同一案由中類，附勝敗與金額 |
| `evaluate.py` | 民事檢索的評估：`python -m retrieval.evaluate` |
| `build.py` | 建立上線用的檢索資料：`python -m retrieval.build` → `artifacts/retrieval_civil_v6/`（索引、遮名後的案件清單、每件判決提到的證據與抗辯類型） |
| `masking.py` | 遮名：顯示判決時把當事人姓名換成【原告】【被告】、第三人換成【關係人】；使用者輸入送出前遮掉身分證字號、電話、電子郵件、地址、車牌與指定的名字 |
| `ner.py` | 用 CKIP 人名辨識找出沒有稱謂的人名，存成檔案給 `build.py --ner-names` 用（需要 torch，另外的環境，見 [docs/遮名.md](../docs/遮名.md)） |
| `masking_audit.py` | 遮名抽查：匯出人工標註表、計算漏遮率（見 [docs/遮名.md](../docs/遮名.md)） |
| `criminal.py` | 刑事設定：用犯罪事實前 600 字建索引，每個主要罪名最多 1,500 件、新的判決優先；遮被告與有稱謂的人名，附宣告刑與司法院原文網址。`python -m retrieval.criminal --data <CAIL 格式 .jsonl>` → `artifacts/retrieval_criminal_v1/`（目前 88,376 件） |

`evaluate.py` 的評估（文字資料集 v5，隨機 3,000 件當查詢，前 10 件）：鄰居勝訴比例的 AUC 0.732（全部案件）、
0.716（同案由中類）；一部勝訴案件的獲償比例，鄰居中位數和實際的絕對誤差中位數 0.193
（一律猜全體中位數是 0.241）。

## 上線語料（`retrieval_civil_v6`）

訓練模型要嚴格篩選，檢索是找真實案例給人看，條件不同，所以語料直接取自 `judgments.db`
（第一審的給付、確認案件，用目前的規則重新推導段落，不寫回資料庫）：

| 層 | 件數 | 勝訴率 | 用途 |
|---|---:|---:|---|
| 對審、有被告答辯（`in_stats`） | 77,116 | 62% | 統計與列表 |
| 對審、沒有實質答辯 | 7,708 | 73% | 只在列表 |
| 一造辯論（`default_judgment`） | 103,511 | 95% | 只在列表，標示「被告未到庭」，最多 3 件 |

一造辯論的被告沒有出庭，幾乎都是原告贏，放進統計會把勝率與金額拉高。

v5（2026-11-17）比 v4 多了 2026 年 1–10 月的 30,004 件（B3 補爬），2022–2025 年的件數和 v4 相同；兩字人名的遮名門檻改成跟著判決件數等比例放大（`masking.scaled_df`），見 `docs/遮名.md`。

v6（2026-11-19）語料相同（多 1 件），改用規則 2.5.4（判決結果與請求金額，分工表 B4）與 2.5.3（段落切分）重新推導：勝訴但判准不到請求 95% 的從 1,429 件減為 876 件；148 件的被告答辯切回來，移進統計層。見 `docs/資料版本.md`。

和 v1（文字資料集 v5 的 46,683 件）比較，同案由中類、前 10 件，統計層（v4 時評估，v5、v6 沒有重跑；索引的建法沒變）：

| 查詢 | 查詢件數 | AUC | 第 1 件相似度中位數 | 一部勝訴的金額比例誤差 |
|---|---:|---:|---:|---:|
| v1 語料裡的案件 | 6,000 | 0.727 → 0.725（無差異） | — | 0.180 → 0.178（無差異） |
| v1 沒收錄的案件 | 3,000 | 0.730 → **0.764** | 0.249 → **0.293** | 0.191 → 0.180（無差異） |

差異的 95% 信賴區間（配對 bootstrap）：v1 沒收錄的案件 AUC +0.022～+0.046，相似度 +0.040～+0.048；其他都包含 0。
也就是原本涵蓋的案件不變，擴充的好處在原本涵蓋不到的案件：這批案件的請求金額中位數約 39 萬，v1 語料約 132 萬。
勝訴率和金額是自動指標，「像不像」還沒有人工評估。

## 民眾口語描述的測試

抽 80 件模型沒看過的真實判決（勝敗各半），排除 8 件民眾不會自己描述的案件，其餘 72 件在不知道判決結果的情況下
改寫成口語（字數中位數 108）。這是模擬，不是真人寫的，樣本也小，只能當初步結果。

| 輸入 | 勝訴 precision | 勝訴 recall | 敗訴 precision | 敗訴 recall | 平均機率 | 第 1 件相似度 |
|---|---:|---:|---:|---:|---:|---:|
| 判決原文 | 0.674 | 0.806 | 0.759 | 0.611 | 0.61 | 0.257 |
| 判決原文截到相同長度 | 0.706 | 0.667 | 0.684 | 0.722 | 0.52 | |
| 民眾口語 | 0.815 | 0.611 | 0.689 | 0.861 | 0.45 | 0.141 |

機率 50% 為切線。這 72 件勝敗各半，真實勝訴約六成，所以 precision 不能直接和全體資料比。口語的平均機率偏低（依真實勝訴率加權後約 0.46，實際 0.60），判勝訴的件數變少，才出現勝訴 precision 高、recall 低的情況，不代表口語比判決原文準。

試過訓練時每件判決多加兩份短版：截短的判決文字校準變好（前 100 字的 ECE 0.076 → 0.024），
但口語沒有改善（選了類型的 AUC 0.722 → 0.697，配對差異不明顯），沒選類型時明顯變差（0.716 → 0.632），所以沒有採用。
