# 真實模型冒煙測試

離線測試與真實模型測試分開：一般 `unittest discover` 不連 HF、不下載模型。`tests.yml` 保留 Python 3.9／3.12，另外在 Ubuntu 以 Python 3.13、`requirements-ci-new.txt` 的較新版 torch／transformers 跑全部離線測試。這組刻意安裝舊 PEFT 0.17.0，以確認不相容的選用套件不會妨礙匯入民事訓練工具或查看 `--help`。

民事訓練程式將 transformers 匯入延後至真正訓練時。這不代表舊 PEFT 可以搭配任何新版 transformers 訓練；要執行訓練仍需使用相容的環境。平台推論繼續使用 `backend/requirements.txt` 的固定版本。

## CI 設定

在 GitHub repo → Settings → Secrets and variables → Actions 新增 `HUGGINGFACE_CI_TOKEN`。使用組織成員個人建立、僅能讀取 `JudgementDigest/judgementdigest-artifacts` 的 Fine-grained token；不需要 Write 權限，不要放入程式碼。缺少 secret 時，冒煙測試會明確失敗。

`model-smoke.yml`：

- main 的模型載入程式、前端或測試設定變更時，用 `.github/model-smoke.json` 指定的固定 HF commit 測試。
- 每天台灣時間 03:23 排程檢查 HF main；先解析成完整 commit SHA，再下載該 snapshot。HF 更新最晚在下一次排程檢查，不是即時 webhook；GitHub 排程可能延遲。
- 可在 Actions → real model smoke → Run workflow 手動執行；勾選 `latest` 可檢查最新發布版。
- HF 發布版確認通過後，更新 `.github/model-smoke.json` 的 `revision`，保留後續程式回歸測試的固定基準。

僅可信任的 main 與手動／排程工作取得 HF secret，外部 PR 不執行此下載流程。下載約 3.5 GB，包含民刑事模型、刑度 ELECTRA 與兩組檢索資料。測試檔案留在 runner，不上傳模型、判決內容或 token 作為 Actions artifact；僅保留版本與通過紀錄。

## 驗證範圍

1. 真實模型經正式後端載入，`/api/health` 的民事、刑事、金額皆須為 `model`，刑度須為 `electra`；退回示例資料或 SVM 即失敗。
2. Chromium 實際開啟民事、刑事結果頁，透過原本 API 發出請求；驗證有相似判決、預測值合法、刑度機率加總約 1，並可切換結果頁籤，沒有瀏覽器 JavaScript 錯誤。
3. 使用合成的使用者描述，不驗證特定罪名是否答對。這是載入與串接檢查，不代替完整準確率評估。

## 本機執行

先安裝 `backend/requirements.txt`、`playwright==1.65.1`，並登入 HF：

```bash
python scripts/download_smoke_models.py --output /tmp/jd-smoke-artifacts
# 加 --latest 可檢查 HF 最新發布版，並記錄解析後的 SHA。
python -m playwright install chromium
cd frontend
npm ci
npm run build
cd ..
JD_ARTIFACTS_DIR=/tmp/jd-smoke-artifacts HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 python -m tests.model_smoke
```

使用獨立測試資料夾，避免覆蓋開發中的 `artifacts/`。測試會在可用的本機埠啟動與關閉自己的 API／前端程序。
