# JudgementDigest 介面改版設計 spec

請重新設計這個網站的視覺與版面。**使用流程、每一步收集的資料、結果頁的內容都保留**，其餘（版面、視覺風格、元件樣式、資訊的排列與強調方式）都可以大改。

---

## 1. 產品是什麼

JudgementDigest（類案判決參考）讓一般民眾描述自己遇到的糾紛，用全國地方法院的真實判決，告訴他「類似的案件通常怎麼判」。

- **民事**：原告贏的比例、可能判准的金額範圍、相似判決、證據對照、對方常見的抗辯
- **刑事**：可能的罪名、法條、刑期分布、相似判決
- 免註冊、不收費，結果只是參考，不是法律意見

## 2. 使用者

- 一般民眾，**沒有法律背景**，多半第一次上法院或還在考慮要不要提告
- 常常焦慮、對結果很在意；容易把機率當成保證
- 年齡層廣，包含年長者；很多人用手機
- 會把結果列印或存成 PDF，拿去給律師、法扶或家人看

設計目標：**讓人安心、看得懂、不誤導**。數字要清楚，但不能讓人以為是保證；說明要白話。

## 3. 一定要保留的流程

```
首頁 /  →  描述案情 /start  →  確認與遮名 /confirm  →  結果 /result/civil 或 /result/criminal
                                                        ↘ 判決導讀 /judgment/:source/:caseId
說明與法律小知識 /guide（從頁首、結果頁的「?」連過去）
```

- 頁首有步驟條：描述案情 → 確認內容 → 參考結果
- 案件類型三選一：**民事／刑事／不確定**。「不確定」時結果頁有民事、刑事兩個分頁
- 結果頁可以「回上一步」「修改描述」，資料保留

## 4. 各頁內容（要全部放得下）

### 4.1 首頁
- 一句話說明產品；主要按鈕「開始查詢」，副標「免註冊，5 分鐘免費查詢」
- 區塊：你會得到什麼、怎麼使用、資料來源、這不是法律意見（附法律扶助基金會）、你的資料怎麼處理、常見問題

### 4.2 描述案情（表單最長的一頁）
1. **這是哪一類的事情？** 民事（要求賠償、還錢、履行契約）／刑事（被警察、檢察官調查，或想告對方犯罪）／不確定。選了之後顯示「選○○，你會得到…」的條列
2. **發生了什麼事？** 大的文字框，範例 placeholder；提示可以直接貼起訴書的「犯罪事實」或「事實及理由」
3. **糾紛類型**（民事）：可多選的下拉，46 類，分 15 大類（侵權、契約、民間借貸、勞動、不動產…）。右側有「糾紛類型說明」側欄，選到的類型會標出來並捲到那裡
4. **打算在哪個法院**（可不選）
5. **幾個基本問題**（民事）：想請求的金額（可輸入「50萬」）、對方是（個人／公司／政府機關、學校、醫院）、有沒有請律師
6. **手上有哪些證據**：勾選「有沒有」，不用上傳（診斷證明、收據、轉帳紀錄、LINE 簡訊錄音、契約借據本票、照片監視器行車紀錄器）
7. 刑事另有「刑事案件怎麼寫」的提示卡
8. 按鈕「下一步：確認內容」，下方說明「送出前會先讓你預覽，並遮掉姓名、身分證字號、電話」

### 4.3 確認與遮名
- **會送出的內容（已遮名）**：顯示描述全文，自動遮掉的身分證、電話、email、地址以**橘色標記**標出；下方可以輸入要另外遮的名字（chips）
- **敏感個人資料同意**：描述含病歷、前科等時出現，「我同意」或「不同意，回上一步刪掉」，沒選不能繼續
- **補充細節（可略過）**：兩種模式
  - 固定題目（不會傳給 AI）
  - 「請 AI 幫我看還缺什麼」→ AI 產生題目；要有載入中、失敗、次數用完、判斷不是法律糾紛的提示
  - 每題：題目、為什麼要問（小字）、回答欄
- **整理成判決書的寫法（建議）**：AI 把口語改寫成判決書用語，使用者可以直接修改、確認或改用原文；若改寫出現原文沒有的數字要醒目提醒
- **你提供的資料**摘要（類型、糾紛、請求金額、對方、律師、證據數）
- 主要按鈕「看參考結果」，不能按時要說明原因

### 4.4 民事結果（最重要的一頁）
頁首：標題「民事參考結果：侵權：交通事故」、一句說明「比對了 30 件案由相同的真實判決」、下載 PDF、回上一步、修改描述；不確定時有民事／刑事分頁。

| 區塊 | 內容 |
|---|---|
| **相似判決的結果** | 30 件裡全部勝訴／一部勝訴／敗訴各幾件（比例條）；訊號提示（強／弱／資訊不足三種文案）；「模型參考：勝訴機率 46%」收在「模型細節」裡；被告未到庭的件數另外說明 |
| **可能判准的金額** | 大字的金額範圍＋「你請求 648,000 元」；一條 0 到請求金額的範圍條；「10 件約有 8 件落在這個範圍」；可展開「看各金額範圍有幾件」的直方圖 |
| **相似的真實判決** | 表格：字號、法院、年份、結果、判准／請求、相似度、動作（判決導讀、原文）；「只看原告勝訴的」切換；一造辯論的判決要標示 |
| **證據對照** | 每項證據：相似勝訴判決提到的比例（條）＋「你有提到 ✓／沒有提到」 |
| **對方可能會怎麼說** | 常見抗辯，名稱＋白話說明＋出現比例 |
| **注意事項** | 不是法律意見、和解撤回的案件不在統計裡、法律扶助基金會連結 |

**金額區塊有兩種來源，標題和說明要不同**（要讓人一眼看出差別）：
- 模型推估（`source = model`）：「如果判決是『一部勝訴』，可能判准的金額」，並說明範圍很寬、全部勝訴通常就是請求的全額
- 相似判決（`source = similar`）：「如果勝訴，可能判准的金額」「依 N 件相似的勝訴判決」
- 沒填請求金額時改顯示比例（3%～90%），並提示回上一步填金額
- 相似判決不夠時顯示「無法估出金額範圍」

### 4.5 刑事結果
- **可能的罪名**：罪名＋法條＋機率，可點選切換；說明用的是原文還是整理後的文字
- **刑期範圍**：6 個區間（拘役、罰金／1～6 個月／7～12 個月／1～3 年／3～10 年／10 年以上）的機率，模型推估與「最相似的 50 件實際宣告刑」兩組並列比較
- **相似的真實判決**：字號、罪名、宣告刑、相似度、判決原文連結
- 注意事項：不起訴、撤回的案件不在資料裡；告訴乃論和解後通常沒有判決；不是法律意見

### 4.6 判決導讀
- 判決的基本資料（案由、結果、判准／請求）
- 判決全文，段落依功能上色（主張、抗辯、爭點、證據、法院判斷），可以勾選要標色哪幾類
- 「關於這些標示」說明；司法院裁判書查詢系統連結

### 4.7 說明與法律小知識
- 長文頁，有目錄：民事和刑事的差別、糾紛類型說明、怎麼看結果、常見名詞、下一步可以怎麼做

## 5. 每個區塊都要設計的狀態

- **載入中**（結果約需幾秒；AI 整理、AI 提問也要等）
- **錯誤**（「出了點問題」＋再試一次）
- **示例資料**：沒有模型時整頁是假資料，要有明顯但不嚇人的標示（頁面上方、各區塊、PDF 上都要有）
- **資料不足**：相似判決不夠、沒有抗辯、沒有證據對照
- 數字很極端時（0 件、100%）版面不能壞

## 6. 範例資料（真實輸出，請用這組做主要畫面）

民事，車禍，請求 648,000 元：

- 相似判決 30 件：全部勝訴 0、一部勝訴 30、敗訴 0；被告未到庭 5 件；訊號「較弱」；模型勝訴機率 46%
- 金額（模型、一部勝訴）：21,087 元～580,339 元，中位數 238,253 元，涵蓋 80%
- 各金額範圍件數（判准比例）：0–20% 7 件、20–40% 8 件、40–60% 12 件、60–80% 1 件、80–100% 2 件
- 證據對照：診斷證明 93%、收據 93%、照片監視器 77%、交通事故鑑定 77%、薪資證明 40%、轉帳紀錄 30%、LINE 簡訊 3%
- 常見抗辯：請求的金額太高 53%、你也有過失（與有過失）23%、損害和行為沒有因果關係 13%
- 相似判決：「臺灣雲林地方法院 113 年度簡字第 106 號民事判決」一部勝訴，請求 918,252、判准 420,350，相似度 0.14

刑事，超商竊盜：竊盜罪（刑法第 320 條）99%；刑期 拘役、罰金 88%／1～6 個月 12%；相似判決 50 件實際宣告刑 拘役、罰金 94%／1～6 個月 6%

## 7. 不能改的內容與原則

- **不要把機率或金額做成「保證」的樣子**：不用儀表板指針、紅綠燈、「你會贏」這類表達；範圍一定要和「10 件約有 8 件」這類說明放在一起
- **免責與注意事項文字要保留**，可以改排版但不能刪或藏到看不到
- 「相似度」不是百分比，顯示成 0.14 這類小數，並保留說明連結
- 勝訴／一部勝訴／敗訴的顏色不要用強烈的紅綠對比（敗訴不要像「失敗警告」），也要有文字，不能只靠顏色
- 遮名用的橘色標記要和其他強調色分得開
- 文案用白話、短句；法律名詞第一次出現要能點開看說明

## 8. 技術與無障礙限制

- Vite + React 19（單頁應用，不是 Next.js）+ Tailwind CSS v4 + shadcn/ui（`base-nova` 風格，底層是 Base UI，不是 Radix）；圖示用 lucide。請用這套元件能做到的設計，或清楚標出需要新元件的地方
- 顏色、字級用 CSS 變數（design tokens），請給出淺色與**深色模式**兩套（網站跟著系統設定切換）
- 字型：Noto Sans TC；內文至少 15–16px，年長者也要讀得舒服
- **手機優先**：375px 寬要能完整使用；結果頁桌機是兩欄（結果＋金額、證據＋抗辯），手機改成一欄；相似判決表格在手機上要有替代排法
- **列印／PDF**：結果頁要能印成報告，展開的細節自動展開、按鈕隱藏、兩欄維持
- 對比至少 WCAG AA；鍵盤可以操作；圖表要有文字替代（例如「全部勝訴 0 件、一部勝訴 30 件」）

## 9. 想要的產出

1. 設計方向：整體風格說明、色票（淺／深）、字級、間距、卡片與按鈕樣式
2. 主要畫面（桌機＋手機）：首頁、描述案情、確認與遮名、民事結果、刑事結果、判決導讀
3. 民事結果頁的狀態變化：金額兩種來源、沒填請求金額、資料不足、示例資料、載入中
4. 列印版的民事結果
5. 元件清單：哪些沿用 shadcn、哪些是新的（例如金額範圍條、刑期分布圖、結果比例條）
