# 模型檔上傳到 Hugging Face

模型、檢索索引這類大檔案不放進 GitHub，統一放在 Hugging Face（HF）的私人 repo：

```
JudgementDigest/judgementdigest-artifacts
```

repo 裡的每個資料夾，對應平台 `artifacts/` 底下的同名資料夾。大家從同一個地方下載，就不會有人拿到舊版。

| 資料夾 | 內容 | 負責 |
|---|---|---|
| `criminal_term/` | 刑度 ELECTRA | 已上傳 |
| `criminal_v1/` | 刑事罪名、法條 SVM | 刑事組 |
| `retrieval_criminal_v1/` | 刑事相似判決檢索 | 刑事組 |
| `civil_winloss_v1/` | 民事勝敗模型 | 已上傳 |
| `civil_amount_v1/` | 民事獲償比例模型 | 已上傳 |
| `retrieval_civil_v3/` | 民事相似判決檢索 | 民事組 |

## 第一次使用

1. 有 HF 帳號，並請管理者把你加進 repo 所在的 HF 組織，角色選 **write**（只要下載的話 **read** 就夠）。
2. 到 https://huggingface.co/settings/tokens 建一個 token，權限選 **Write**。token 不要貼到群組、程式碼或 `.env` 以外的地方。
3. 安裝並登入：
   ```bash
   pip install -U "huggingface_hub[cli]"
   hf auth login        # 貼上剛才的 token
   hf auth whoami       # 確認登入的是自己的帳號
   ```

## 上傳

在**放模型檔的資料夾的上一層**執行。以刑事 SVM 為例，本機的檔案在 `artifacts/criminal_v1/`：

```bash
hf upload JudgementDigest/judgementdigest-artifacts \
  artifacts/criminal_v1 criminal_v1 \
  --delete "*" \
  --commit-message "criminal_v1：重訓（2026-11-12，charge top-1 0.981）"
```

- 第一個路徑是**本機**資料夾，第二個是 **HF 上**的資料夾名稱。HF 上的名稱一定要和平台用的一樣（上面表格），不要加日期或自己的名字。
- `--delete "*"` 會先清掉 HF 上這個資料夾裡、這次沒有上傳的舊檔案，避免新舊檔案混在一起。只影響這個資料夾，不會動到別人的。
- `--commit-message` 寫清楚是哪個資料夾、改了什麼、分數多少。之後要查是哪一版，就看這裡。
- 檔案很大時（例如民事檢索 2.4 GB）會分好幾次上傳。中斷的話，重跑同一個指令會接著傳。
- 不確定時，加 `--create-pr`：這次上傳會變成 HF 上的一個 PR，確認沒問題再合併。

### 從 Kaggle 直接上傳

在 Kaggle 訓練完不用先下載到自己電腦。把 token 存進 Kaggle 的 Secrets（Add-ons → Secrets，名稱 `HF_TOKEN`），在 notebook 最後加：

```python
from huggingface_hub import HfApi
from kaggle_secrets import UserSecretsClient

api = HfApi(token=UserSecretsClient().get_secret("HF_TOKEN"))
api.upload_folder(
    repo_id="JudgementDigest/judgementdigest-artifacts",
    folder_path="/kaggle/working/criminal_term",   # 輸出的資料夾
    path_in_repo="criminal_term",                   # HF 上的名稱
    delete_patterns="*",
    commit_message="criminal_term：重訓（說明改了什麼、分數）",
)
```

## 每個資料夾裡要有什麼

- 平台載入需要的所有檔案（不確定的話，看 `backend/README.md` 的「模型與資料」，或問負責串接的人）。
- 一個 `README.md`，寫：
  - 訓練日期、用的程式（例如 Kaggle notebook 名稱或 repo 裡的檔案）
  - 訓練資料的範圍和切分方式（例如「2016–2024 訓練、2025 測試」）
  - 測試分數
  - 和上一版差在哪裡

## 不要上傳

- token、帳號密碼、`.env`
- 訓練用的原始資料（`.jsonl`、`judgments.db` 這類）。檢索資料本來就需要判決內容，可以上傳，但 repo 一定要維持**私人**。
- 實驗用、平台用不到的檔案（各種 checkpoint、log、暫存檔）

## 格式改了怎麼辦

- **重訓、格式不變**（檔案名稱和內容格式一樣，只是權重不同）：直接上傳到同一個資料夾，平台不用改程式。
- **格式變了**（檔案改名、模型架構改了、輸出不同）：平台的程式也要改。先在群組講，用新的資料夾名稱（例如 `criminal_v2/`）上傳，並開 GitHub PR 改程式。舊資料夾等 PR 合併後再刪，平台才不會壞掉。

## 上傳完

1. 確認 HF 上的檔案是對的：
   ```bash
   hf download JudgementDigest/judgementdigest-artifacts --include "criminal_v1/**" --dry-run
   ```
2. 在群組說一聲：哪個資料夾、改了什麼、分數多少。
3. 其他人重跑同步指令就會拿到新版（見根目錄 README 的「模型檔（Hugging Face）」），只會下載有改過的檔案。
