# 刑事判決書結構化規則

目前正式流程已啟用「新版逐罪配對＋空槽舊版備援」，詳見[正式 fallback 驗證與輸出](formal_fallback_20261020.md)。[訓練標籤品質修正](training_label_quality_20261019.md)的准入檢查保持不變。下方歷次比較保留其當時口徑，不能當作目前訓練資料量。

## 輸入與輸出

程式讀取原始工作表「裁判書資料」，每件裁判輸出一列至「罪法刑結構化」。此工作表仍以案件為單位彙整欄位；萃取時則與 `build_structured_review.py` 共用逐罪對齊規則，後者另外保留逐罪的巢狀結果。不按被告拆列。

「裁判字號」、「裁判書連結」、「裁判種類」及「案件類型」直接複製原始欄位；其餘欄位由規則萃取。多值欄位依原文出現順序去除重複，儲存為 `[A,B,C]`；沒有值時寫成 `[]`。

## 案件結果

案件結果只看「主文」：

| 結果 | 定義 |
|---|---|
| 有罪 | 出現「犯……罪」，或「處死刑／無期徒刑／有期徒刑／拘役／罰金」 |
| 無罪 | 沒有定罪句型，但出現「無罪」 |
| 不受理 | 沒有定罪句型，但出現「不受理」 |
| 免訴 | 沒有定罪句型，但出現「免訴」 |
| 混合 | 同一主文同時出現定罪句型及「無罪／不受理／免訴」 |
| 其他 | 以上句型皆未出現，常見於程序裁定、附帶民事或上訴駁回 |

若同時出現數個非有罪結果，會以 `／` 合併，例如「無罪／不受理」。

## 法條萃取

### 來源順序

1. 主文同一罪刑子句若明載法條，優先使用。
2. 否則依序檢查「事實及理由／理由」、「事實／犯罪事實」、「適用法條」。先找原始名稱精確配對，暫存粗分類候選；較後來源的精確配對優先於較前來源的粗分類。已知主文罪名配對時，結尾的「罪」可省略，也容許「罪嫌」寫法；統一「共同犯／共同」及名稱前的「幫助犯」寫法，不使用任意子字串當精確名稱。「罪嫌」容錯僅限精確主文名稱，不據此新增主文罪名。粗分類候選須保留既遂／未遂、致死、電腦詐欺的差異；候選名稱唯一，或所有候選名稱的逐項法條集合完全相同，才可採用最優先來源。法條集合不同的歧義仍留空。
3. 新版遇到無法解析的其他罪名敘述，停止把前方的法條承接到後罪。「同法／前開條例」及省略法名的後續條號，先在同一編號大點內解析。連續項、款只在緊接完整引文時展開，例如「第4條第3項、第6項」與「第1項第2款、第1款」，不跨罪名承接。
4. 新版所有非空槽保留；僅主文罪名空槽進入 `law_fallback.py`。先排除新版配對歧義，再把現行法院可接受段落交給舊版匹配；不使用檢方附件作為新增備援來源。候選仍須通過否定／檢方主張重疊、已解析其他罪名、不完整並列對應與完整法條字串檢查。有任一拒絕原因就整組留空。成功者來源標成 `舊版備援（理由／適用法條／案件法條備援等）`，不標成法院精確配對；`法條備援紀錄`保留原候選、來源、拒絕原因及引用片段。

備援仍可能將尚未解析的其他罪法條、一般條文放進空槽；已知錯配與缺核心案例見驗證報告。來源篩選不等於已證明逐罪配對正確，也不會為了補空新增罪名。`build_row(..., use_fallback=False)` 可重現新版單獨結果；所有正式入口預設開啟備援。

例如「刑法第140條第1項之侮辱公務員、同法第309條第1項之公然侮辱罪嫌」，主文為「侮辱公務員罪」時只配第140條。相反地，同一罪的多條引用，例如「刑法第216條、第210條之行使偽造私文書」，仍可成組保留。

### 固定文字與結構

法條必須符合下列概念結構：

```text
係犯／係幫助犯／共同犯／違反／適用／應依／依／按／犯 + 法規名稱 + 第N條 + [之N] + [第N項] + [第N款]
```

例如：

```text
核被告所為，係犯毒品危害防制條例第10條第2項之施用第二級毒品罪
→ [毒品危害防制條例第10條第2項]
```

法規名稱必須以「法」或「條例」結尾。數字支援阿拉伯數字、中文小寫及法院常用大寫數字。程式會排除「刑事訴訟法」及「刑法施行法」，因為它們通常是程序或施行依據，不是定罪法條。

## 罪名萃取

### 不能安全駕駛的酒／毒分類

原始罪名保留原文。只有「不能安全駕駛」或僅有第185條之3主條號，不能直接指定酒駕／毒駕。

1. 優先使用罪名中明載的酒精、毒品／具體藥物，或其明確引用的第185條之3第1項款別。此專案2018–2025資料中，第1、2款屬酒精；第3款及新增第4款屬毒品相關規定。修正沿革參見[法務部立法理由](https://mojlaw.moj.gov.tw/LawContentReason.aspx?LSID=FL001424&LawNo=185-3)。
2. 主文未指明時，找對應駕駛罪的論罪句及其款別；再以同句明確的施用／飲酒後駕車、實際酒測數值補充。單獨出現藥名、同案有施用毒品罪、前案或泛論法規，都不直接決定本罪種類。法規的完整引文須先排除再切句，避免引文後半段被誤當成事實。
3. 主文明示酒毒／雙款，或同一駕駛罪的論罪法條群組、論罪科刑句明確認定酒毒後駕車時，輸出「酒駕罪」「毒駕罪」雙標籤。整段只有兩個關鍵字、同案其他施用罪、前案、法條引文、兩個不同論罪群組，均不直接判定混合。名稱與單一款別矛盾或證據不足時仍留空。這是保守規則，並非完整的語意／行為人指涉分析。

`build_structured_review` 使用同一逐罪流程的上下文分類結果。「罪名（標準化）」提供展平後的標籤；新增「罪名（對應標準化）」以巢狀清單與原始罪名、法條、宣告刑逐筆對齊，例如一罪雙標籤為 `[["酒駕罪","毒駕罪"]]`，不複製罪刑筆數。`refresh_modeldata` 依此欄位驗證每罪是否標準化完整，再將模型的 accusation 展平去重；仍相容舊版一罪一類資料。舊 `normalize_workbook` 只在原始「裁判書資料」工作表有同案號及連結的唯一資料列時補查上下文；缺來源或有歧義時留空。

### 來源順序

1. 優先讀取「主文」明載的「犯○○罪」。
2. 主文沒有「犯○○罪」但有「被告名＋罪名描述＋處／科」時，保留這段描述，不以理由正式名稱覆寫。罪數相同不能作為把「施用」換成「販賣」等其他罪名的理由。
3. 主文沒有具體罪名時，才讀取「事實及理由」與「理由」中的論罪句。
4. 理由仍未命中時，最後以「事實」與「犯罪事實」補充。

### 固定文字與結構

程式會先截掉主文欄中可能誤併的「犯罪事實及理由／事實與理由」後文，再擷取「犯○○罪」。罪名可以包含逗號，但包含「附表」且以「所示／欄」引用附件的文字不算罪名。主文沒有具體罪名時，輔助欄位先找出完整法條，再從法條結尾緊接著擷取到「罪」。法條與罪名間的「之」可以有也可以省略，罪名內部出現的「之」會完整保留：

```text
係犯……第N條之○○罪
係犯……第N條○○罪
違反……第N條之○○罪
```

主文主要擷取：

```text
被告犯○○罪
```

例如：

```text
係犯毒品危害防制條例第10條第2項之施用第二級毒品罪
→ [施用第二級毒品罪]

係犯刑法第185條之3第1項第3款之駕駛動力交通工具而有尿液所含毒品達行政院公告之品項及濃度值以上之情形罪
→ [駕駛動力交通工具而有尿液所含毒品達行政院公告之品項及濃度值以上之情形罪]
```

若主文只寫「犯如附表所示之罪」，而理由也沒有明載罪名，程式不猜測附表內容，會保留 `[]` 並標記「需人工核對」。

## 刑期萃取

刑期只讀取「主文」，並將每罪的宣告刑與法院明載的應執行刑分欄保存。程式不自行加總宣告刑，也不以單一宣告刑代替應執行刑。

### 所有宣告刑

尋找：

```text
處／科 + 刑種 + 數量
```

支援死刑、無期徒刑、有期徒刑、拘役及罰金。相同刑度可能分別屬於不同罪或不同被告，因此宣告刑不去除重複：

```text
各處有期徒刑參月；另處有期徒刑參月
→ 所有宣告刑：[有期徒刑參月,有期徒刑參月]
→ 宣告刑（月）：[3,3]
→ 宣告刑最大值（月）：3
```

`宣告刑（月）`會依原順序換算有期徒刑與拘役：有期徒刑以「年 × 12 ＋ 月」計算，拘役以「日 ÷ 30」計算並保留小數二位。罰金、無期徒刑及死刑不強制換算成有限月數，因此不會出現在月份清單。`宣告刑最大值（月）`是所有可換算自由刑的最高值，不是總和，也不是法院最終應執行刑。

### 應執行刑

另行尋找：

```text
應執行／應執刑 + [之刑為] + 刑種 + 數量
```

宣告刑及應執行刑支援的格式包括：

- `死刑`
- `無期徒刑`
- `有期徒刑N年[N月]`
- `有期徒刑N月`
- `拘役N日`
- `罰金[新臺幣]N元`

例如：

```text
各處有期徒刑參月。應執行有期徒刑壹年貳月。
→ 所有宣告刑：[有期徒刑參月]
→ 宣告刑（月）：[3]
→ 應執行刑：[有期徒刑壹年貳月]
→ 應執行刑（月）：[14]
→ 是否明載應執行刑：True
```

沒有「應執行／應執刑」時，`應執行刑`及`應執行刑（月）`保持 `[]`，`是否明載應執行刑`為 `False`；程式不將宣告刑相加或填入應執行刑。

### 併科罰金與易科罰金

`併科罰金`是法院另行宣告的罰金刑，會保留；`易科罰金`是自由刑的替代執行方式，不視為另一筆宣告刑：

```text
處有期徒刑肆月，併科罰金新臺幣壹萬元
→ [有期徒刑肆月,罰金新臺幣壹萬元]

處有期徒刑肆月，如易科罰金，以新臺幣壹仟元折算壹日
→ [有期徒刑肆月]
```

少數省略「刑」的「有期徒陸月」會正規化為「有期徒刑陸月」。

## 刑期資料狀態

| 狀態 | 定義 |
|---|---|
| 有應執行刑 | 主文明載「應執行／應執刑」 |
| 僅宣告刑 | 有抓到宣告刑，但沒有明載應執行刑 |
| 多被告未配對 | 「被告／相對人」包含多位名稱、主文有多個宣告刑，且沒有明載應執行刑 |
| 無刑期 | 主文沒有命中支援的宣告刑或應執行刑 |

「多被告未配對」只是資料品質提示。程式不依被告人數推算罪數，也不將刑期配對至特定被告。

## 萃取狀態

| 狀態 | 定義 |
|---|---|
| 完整 | 主文至少抓到一個宣告刑或應執行刑，且有罪／混合案件已抓到法條與罪名 |
| 需人工核對 | 主文引用附表但沒有抓到罪名，或有罪／混合案件沒有抓到法條或罪名 |
| 無刑期 | 主文未命中支援的應執行刑或宣告刑句型，也沒有因缺法條或附表而被改標為人工核對 |

「完整」表示規則所需欄位已經有值，不代表內容經人工確認百分之百正確。「無刑期」較精確的意思是「未擷取到刑期」；它可能是無罪、程序裁定、免刑、上訴駁回，也可能是原文採用尚未支援的寫法。

## 已知限制

- 不解析 Excel 內或裁判附件中的附表結構。
- 「罪法刑結構化」仍把逐罪結果彙整成案件層級清單；需要保留罪法刑位置對應時，使用 `build_structured_review.py` 的巢狀輸出。兩個入口共用萃取規則，但都不按被告拆列。
- 不建立宣告刑總和；多個宣告刑沒有明載「應執行」時，不推算應執行刑。
- 「免刑」沒有可量化刑期，不填入應執行刑；刑期只在引用判決或附表內時也不推測。
- 原文錯字、異體字或法規簡稱會照原文保留，仍需人工抽樣確認。

### 法條配對與模型類別篩選

`refresh_modeldata` 保留逐罪原始法條與部分標準化結果，另判斷是否能提供完整的訓練答案。罪名與法條任務均要求罪名來源為「主文」；理由／事實備援及「主文刑期＋理由／事實正式罪名」尚未核實主文／附表，兩任務排除。法條任務還要求槽數一致、每罪至少一條、每條字串完整可解析。部分缺法、未解決法名回指、法名前殘文、解析器不認得的法名／格式，均有明確排除原因。這些條件不能證明所有項款完整或語意正確。

法條不需通過固定頻率白名單；例如白名單外的著作權法第93條仍能成為標籤。沿用既有法名解析器，不新增法名清單；解析器尚不認得的真法條保留原文、列待確認，不宣稱它是錯法條。模型標籤沿用「法律名稱＋主條號」，合併項款與條之幾的粒度不變。

`raw_laws_by_offense`、`standard_laws_by_offense`、`partial_accusation` 與 `partial_relevant_articles` 保留稽核證據；後者只含成功解析的鍵，不能直接拿來訓練。無效任務的 `accusation`／`relevant_articles` 清空，`task_validity` 為 false，原因見 `task_exclusion_reasons`。下游必須跳過該任務或遮罩其 loss，不能把空標籤當成全負答案。目前已用鄰近 `BERT-base-prediction/Taiwan/judgment_bert/data.py` 的實際 `prepare()` 驗證空標籤會被跳過；該入口沒有直接讀取 validity，其他消費者須遵守相同契約。

訓練端依訓練年份計算 `freq >= 30` 類別，再對各集合取交集；這是准入之後的步驟。既有模型資料與已準備的 split 未重建，不會因程式修改自動更新。

### 2026-10-19 早期交接修正（歷史順序）

此節記錄先前版本；目前萃取順序見[非否定詞修正報告](law_extraction_nonnegative_20261019.md)，訓練准入以上節為準。

1. `build_row` 合併並去除來源文字的排版空白；`extract_aligned_case` 先在同一編號大點解析承前法名、條號及連續項款，再由主文取得逐罪紀錄。主文保留在輸出欄位中；理由不能只憑罪數相同改寫主文罪名。
2. `matched_laws` 優先取主文同一罪刑子句的明載法條。沒有時依理由、事實、適用法條順序搜尋，沒有整案法條備援。
3. `conviction_passages` 先依句號／分號切段，再定位檢方主張的起點。檢方主張之前的法院論罪可以保留；後面只有明示「惟本院／惟核被告／本院認…」等返回法院判斷的文字才重新接受。理由與事實還必須通過論罪入口：包括「係犯」「是犯」「係違反」「係幫助犯」「係共同犯」「分別犯」等。片段含不成立、不構成、無罪等否定訊號時仍保守排除，不以刪除關鍵字的方式強行配對。
4. `law_charge_groups` 定位法條，排除程序法／施行法，把緊接的連續法條暫存在同一組。下一個法名的邊界採清理後法名的實際位置，防止正則把前一罪的「共同犯…罪及」吃掉。法條後的前段／後段只在罪名定位時略過；原始主文與理由來源保持不變，配對清單目前保留到條／項／款。
5. 罪名擷取先嘗試一般「之＋罪名＋罪」；其次接受以「汽車駕駛人／駕駛動力交通工具／未經許可」起首、含逗號的長罪名；再嘗試酒毒駕駛的特定長名稱；最後用已知主文名稱作尾綴可省略的錨點。這些模式不任意跨過下一個法條。已配到罪名就結束該組；遇到未解析敘述，也清除暫存法條，避免前罪法條掛到後罪。
6. 名稱精確配對先返回；所有來源均無精確配對時才判斷粗分類候選。既遂／未遂不互換，「致人於死／致死」視為同一結果用語，電腦詐欺不與一般詐欺混配。主文已明載駕駛行為時，理由泛稱「公共危險罪」須緊接刑法第185條之3，且款別酒／毒不能與主文明示種類相反，才可作駕駛罪候選；不接受其他公共危險法條，也不以此捷徑處理主文致死／重傷。多名稱若引用不同法條集合仍不猜測；集合逐項相同才允許返回最優先來源。
7. 當時 `refresh_modeldata` 允許部分罪有法條即送訓練，並把未解析字串當標籤；此准入漏洞已由[訓練品質修正](training_label_quality_20261019.md)取代。部分原始證據仍保留，模型訓練頻率門檻仍是另一個步驟。

此處的「原始對應法條」表示與該罪成組的引文，可能包含同罪的幫助／加重規定，例如刑法第30條、道路交通管理處罰條例第86條；並非宣稱每一條都是獨立定罪條文。配對成功、標準化成功及法律上獨立定罪條款是不同概念。

剩餘限制：僅寫「第X條之罪」、引用附件而本文無具名配對、含頓號的複合罪名、原文漏字／異體字、跨句否定範圍與行為人指涉仍可能漏抓或判斷不完整。句型規則不是全文語意審判；空值與非空值都不能直接當作正確率。本次未建立無條件法條備援，也未覆寫原始資料庫、既有訓練資料或模型。
