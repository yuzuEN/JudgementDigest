## 正式處理順序與邊界

1. `extract_aligned_case` 先定位主文罪名、逐罪切槽、解析同法等回指，交給現行 `matched_laws` 精確／受限粗類比對。新版非空結果不變。
2. 僅主文罪名空槽進備援；理由推得的罪名、附表未核實罪名不因備援變成主文來源。新版有候選歧義就拒絕，並顯式傳遞不完整並列法條資訊，不使用 trace/profile。
3. 用現有 `law_matching_sources`、`conviction_passages` 選法院可接受段落。延續否定／檢方主張政策、`各犯行時` 排除、局部量刑引用遮罩、新舊法暫擬比較遮罩；不新增通則條號或法名黑名單，不以「加重」兩字刪除法條。備援不新增附件採用。
4. `law_fallback.py` 移植舊版小範圍 matcher；只有受篩選後的來源文字可以傳入。沿用目前罪名 normalizer，沒有復活舊版將不明不能安全駕駛一律當酒駕的規則。候選若與否定／檢方引用重疊、已解析其他罪名衝突、並列配對不完整、法條字串不能完整解析，整組拒絕。無可信候選就留空。
5. 成功來源標為 `舊版備援（理由／適用法條／案件法條備援等）`。新增逐槽 `法條備援紀錄`，包含原候選、來源、拒絕原因、可回查引用片段；modeldata 存在 `meta.reextraction.law_fallback`。原始 judgments 不寫入；完整原文在原始 DB 與本輪 evidence 檔保留，過往 audit 快照雜湊不變。
6. 最後套用原有標準化及 `apply_review` 訓練准入。正式預設開啟；`build_row(..., use_fallback=False)` 僅供同口徑新版對照。

`structure_tasks.structure_row`、`build_structured_review.build_row`、結構化匯出、`refresh_modeldata` 共用正式入口。移植 matcher 不依賴 `/tmp`、歷史 Git 檔案、audit 快照、實驗模組或追蹤技巧。兩個原本斷言「新版空槽」的測試改為明示 new-only，並新增正式來源與已知弱來源限制測試，沒有把錯配包裝成正確。

## 部分標準化政策（維持原狀）

- 原始與逐槽標準化證據允許部分成功：成功值保留，失敗位置保留空字串／空槽，不清掉成功的同案結果。
- 罪名訓練要求所有已觀察主文罪名完整標準化。
- 法條訓練要求主文來源、罪法槽位一致、每槽非空、每個原始法條完整可解析；不要求每條都通過頻率白名單。部分空槽或混有無法解析字串仍無效，active labels 清空但 raw／partial 證據保留。
- **本次錯誤評估以法名＋條號（含之幾，不含項款）逐罪槽判定。現有模型標準化仍會合併條之幾及項款，本輪依範圍不修改。** 比較沒有拿這個較粗的訓練標籤去掩蓋 185之3／185之4 等錯配。
