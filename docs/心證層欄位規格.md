# 心證層欄位規格（交接用）

判決理由中「法院怎麼形成心證」的欄位規格：爭點、證據與採信、舉證責任與心證強度。
這些欄位**尚未實作**，供負責心證分析的同學參考；每一項都附上抽取位置與建議規則。
實作後請寫進 `structuring.py`，並在 [欄位說明.md](欄位說明.md) 補上欄位說明。

## 1. 爭點

| 欄位 | 型別 | 抽取規則 |
|---|---|---|
| `issues[]` | list[str] | 理由段落中「兩造爭執之處」「本件爭點厥為」「爭點如下」之後到下一個編號標題之間的內容，依編號切分 |
| `n_issues` | int | 上者的長度 |

## 2. 證據

| 欄位 | 型別 | 抽取規則 |
|---|---|---|
| `evidence_types[]` | list[str] | 以詞典比對理由段：書證／證人證述／鑑定／勘驗／當事人訊問／錄音錄影／LINE 對話／監視器／診斷證明／公文書／函詢 |
| `evidence_credited[]` | list[{type, credited}] | 在每個證據詞的 **±40 字**視窗內掃描評價詞：<br>採信 = 堪信／可採／足認／應堪採信／非虛<br>不採 = 不足採／無可採／不可採／難認／尚難／無足取 |
| `expert_opinion` | 0/1 | 是否出現「鑑定報告」「鑑定意見」 |

> 這是全部欄位中**最容易做錯**的一項。±40 字視窗會跨到相鄰句子，
> 必須以句號切分後再取視窗，且要處理「雖…堪信…然…不足採」這類轉折。
> 建議先寫驗證腳本跑全量、抽樣 50 筆人工核對，再寫進正式程式
> ——這是本專案既有欄位一路採用的流程。

## 3. 舉證責任與心證強度

| 欄位 | 型別 | 抽取規則 |
|---|---|---|
| `burden_of_proof_cited` | 0/1 | 是否引用民事訴訟法第277條，或出現「舉證責任」 |
| `burden_allocated_to` | str | 「應由原告／被告負舉證責任」的受詞 |
| `conviction_strong` | int | 「堪認」「足認」「應堪認定」出現次數 |
| `conviction_weak` | int | 「難認」「尚難認定」「顯有疑義」「不無疑問」出現次數 |
| `cited_supreme_court[]` | list[str] | `最高法院\d+年度台上字第\d+號` 的全部出現 |
| `cited_precedent_count` | int | 上者去重後的數量 |

## 4. 建議的分析設計

有了這些欄位之後，即可回答：

- **「法官是否對特定類別總是採用特定證據？」**
  `judge × case_type_category × evidence_type` 的條件機率，
  與全體基準線比較後做卡方檢定（多重比較要做 Benjamini–Hochberg 校正）。

- **「法官是否總是判特定結果？」**
  以 `outcome` 為依變數、`judge` 為固定效果，
  控制案件特徵變數（見 [欄位說明.md](欄位說明.md) 的「結構化：當事人與程序特徵」）後跑 logistic regression。
  目前環境沒有 statsmodels/scipy，需先 `pip install statsmodels`。

- **「法官對某類證據的採信率是否異於同儕？」**
  `evidence_credited` 攤平後，以法官為分組計算採信率，
  並以案件組合調整（以案由大類的全體平均為基準線計算期望值）。
