## 文字萃取順序

1. **先辨別來源欄位，再串接文字。**「事實及理由」→「理由」組成理由來源；「事實」→「犯罪事實」組成事實來源。「適用法條」另行處理。可辨認的附件標題或檢方程序結尾會分離出附件，避免後面檢方欄位的結尾把前面的法院欄位一起排除。沒有加入全案 `full_text` 法條補值。
2. **以主文建立逐罪槽位。**先抓「犯……罪」；未寫「犯／罪」時，以被告名後至刑罰前的描述作罪名。句號、分號及「，又／另＋新罪描述」可分槽，不把後一罪複製成前一罪。主文有名稱時，不再以理由正式名稱覆寫原始名稱；仍保留既有名稱清理及罪數尾碼清理。若「事實即理由」段誤併入主文，只在萃取視圖將該明示段落搬回理由；原始主文欄不覆寫。
3. **在匹配視圖解析引用。**同編號段落內承接「同法／同條例」，再展開連續條、項、款；「同條第2項」及緊接罪名的「甲罪、第2項之乙罪」只能承接同段最近明示的條號，新段落不繼承。句內「犯罪事實一（二）」不當成新段落。補齊明示法名後省略的「第」（如「刑法336條」）、「第10條1項」及「刑法第304第1項」的缺「條」寫法。「修正前／後」不當成法名的一部分。原始資料庫文字不改，展開後的法條是可追溯的完整引用，不是法條全文的逐字拷貝；前後段資訊目前仍未納入輸出字串。
4. **先看主文同罪子句明列法條。**有則採用。沒有時，依「理由→事實→適用法條」尋找。理由、事實須有法院論罪入口；各來源仍經原有否定詞／檢方主張排除。
5. **每個法條群組內先比已知主文名稱。**尾端「罪／之罪／罪嫌」可有可無，也可接「之犯行／行為」。這條分支在一般正式罪名 regex 前，避免長罪名必須先被「……罪」解析成功。允許的等義寫法有明確邊界：如「致人於死／致死」、「未經許可，持有／未經許可持有」、「明知為禁藥而轉讓／轉讓禁藥」。扶助義務的完整遺棄描述另要求法院實際引用刑法294條第1項，不能配成293條的一般遺棄。
6. **一般 regex 與有限的長名稱分支。**已知名稱沒有命中時，依序處理一般「法條＋正式罪名」、燒燬罪的住宅／建築物列舉、汽車駕駛人等含逗號長名稱、185條之3駕駛罪名稱。只有已知主文名稱可省略尾綴；不把任意法條後文字當新罪名。頓號未全域刪除，不同罪之間仍分組。
7. **省略並列詞先核對項次，再分配。**「毒品條例10條第1、2項之施用第一級、第二級毒品」只在兩個項次均明列且吻合級別時，給第一級第1項、第二級第2項；同樣接受「第1級及第2級」與「第壹級與第貳級」。不依列表位置猜測，也不把兩項都複製給兩罪。缺項、只有第10條、不同條號均不猜。此展開只服務已知主文罪名，不向未核實的附表主文新增兩個罪名。
8. **精確／等義配對先於粗分類。**找不到才考慮既有罪名標準分類相同的候選；保留未遂、致死、重傷、電腦犯罪、取財／得利差異。毒品級別的「第一／第壹／第1」及純質淨重「二十／20公克以上」只在匹配鍵統一，級別與重量值仍須相同，不能把第三級配到第二級或把5公克視為20公克。多種候選名稱的法條集合不同則留空，集合相同才保留。較後來源的精確法院配對可優先於前面粗分類。
9. **法院採用的附件最後才用，且只精確／等義配對。**法院直接配對及無歧義粗分類均優先。附件必須有實際正文、主文罪名能對上，並符合下列之一：法院明示採用論罪／法條，且採用段落沒有實體法條更正（單純增列程序法可接受）；或法院只引用事實／證據，但其結論另明列同一條項款。若法院文字涉及檢方主張或變更起訴法條，不能走概括採用法條分支，仍需逐條法院結論佐證。通過採用檢查後，附件可以寫「係涉犯／罪嫌」，不再強制要求法院式「係犯」入口；附件內的否定詞及檢方主張標記照原規則排除。來源標為「法院引用附件（原欄位）」；不能用附件的一串法條填滿所有罪。句中「引用附件臺灣……處刑書之記載」不是正文起點，須看到標題後的案號或被告欄等正文訊號才分離附件。
10. **仍無法逐罪歸屬就保留空槽。**不從全案法條清單回填。沒有主文罪名時，既有法院理由／事實正式罪名備援仍存在；若主文只指附表而附表未核實，該備援不能當作已核實的主文最終定罪。

## 部分標準化與模型資料政策

| 階段 | 保留政策 |
|---|---|
| 原始罪名與逐罪法條 | 每槽獨立，找到的法條保留；另一罪缺值不會把整案歸空。名稱不能標準化，仍可透過原始名稱精確配法條。 |
| 法條標準鍵 | 每條獨立處理。未知／不在白名單的條文在標準鍵位置留空字串，原始引用仍保留，`標準化缺值欄位` 標記「法」。審核表既有欄位不細分原因；本次另輸出 `standardization_gaps.jsonl`，逐案、逐罪、逐法條記錄原文、解析鍵及 `no_parseable_law_key`／`not_in_current_whitelist` 原因。不能將標準鍵空值當成沒抓到法條。 |
| 審核表罪名標準化 | 各罪保留各自標準化結果；可同時有成功及未成功的槽位。此次沒有修改罪名白名單。 |
| `refresh_modeldata.apply_review` 的法條任務 | 原有政策不變：有罪、單被告、槽數一致，且至少有一個相關原始法條即可保留。由原始法條取得「法名＋條號」，不能解析時保留原始字串；不要求每罪有法條，也不要求通過固定白名單。 |
| 模型資料的罪名任務 | 原有政策較嚴：所有原始罪名槽位須能標準化且對齊才將 `accusation` 視為有效；部分成功仍留在稽核欄 `partial_accusation`。這不會連帶讓法條任務失效。 |

本次驗證只重新計算萃取與審核輸出；上述模型資料轉換政策以程式及測試核對，沒有重新產出既有模型資料或重跑訓練。全空、部分空及標準鍵全空分開報告，空值率也不等於配對準確率。
