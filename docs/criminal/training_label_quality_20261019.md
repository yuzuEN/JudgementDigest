# 訓練標籤品質修正（2026-10-19）

本輪以已完成非否定詞修正的本機版本為基準，只修改 `refresh_modeldata.py` 的訓練准入。萃取程式、否定詞及檢方主張篩選均未變更；既有修改保留並一併提交。沒有新增召回規則、回填案件法條或解析缺失附件。原始資料庫、既有模型資料、prepared splits、模型與 reviewer 證據均未覆寫。

## 現在的資料契約

1. **萃取與訓練資格分開。**逐罪原始法條、標準化槽位、原始罪名照存；罪名與法條任務均要求 `罪名來源 == 主文`。`理由／事實備援`、`主文刑期＋理由／事實正式罪名` 及缺少來源者，標記 `unverified_charge_source`，不送這兩個任務訓練。這是保守准入，並非宣稱所有備援結果都錯。
2. **每一罪都要有可解析法條。**有罪、單被告、原始罪名／法條槽數一致、每槽非空、每條引文完整可解析，才可設定 `article=true`。只有其中一罪有法條不再視為完整答案。每槽有值只是必要條件，不能證明項款、共用條文或語意完整。
3. **不把未解析字串當類別。**不再使用 `extract_law_keys(raw) or [raw]`。完整字串須通過既有法名解析器與條／項／款格式檢查；未解決的「同條例／前揭條例」、法名前殘文、未知法名／格式分別記錄原因。`invalid_law_strings` 保留原字串及從 0 開始的罪名／法條索引；這個品質欄位包含「尚未解析」，不等於法律上錯誤。
4. **不使用固定頻率白名單作准入。**例如不在 `normalize.LAW_WHITELIST` 的著作權法第93條仍接受。沿用原有解析器，不擴張硬編法名表；解析器不認得的真法條仍保留於 raw，暫不作標籤。例如文化資產保存法第103條目前屬此限制，不能把其排除數宣稱為修掉錯標。模型鍵仍合併項、款及「條之幾」為主條號，沒有改變既有分類粒度。
5. **部分成功保留在稽核層。**`partial_relevant_articles` 只留成功解析的鍵；`partial_accusation` 留成功標準化的罪名；`raw_laws_by_offense`、`standard_laws_by_offense`、`standard_charges_by_offense` 保持逐罪對齊。某一項失敗不清掉其他稽核證據，但不完整任務的 active labels 為 `[]`，`task_validity=false`，原因在 `task_exclusion_reasons`。其他任務獨立判定，例如法條不明不會自動取消可用罪名或主文明載刑期。

消費者必須先排除無效任務，或遮罩該任務的 loss；**未知法條不等於已確認適用法條為空，不能編碼成全負標籤**。不得直接將 `partial_*` 當完整答案。舊模型資料不會因這次程式變更自動更新。

reviewer 按 ID 排序後以 seed `20261019`，從 2,707 案無放回抽 100 案，逐案核對原文：85 案本罪核心法條有支持且已返回條文未混其他罪／一般條文；11 案部分抓對但混抓／錯位；2 案不對應或法院未採用；1 案只有刑30而漏339；1 案原文矛盾待確認。85 案並不保證全部項款齊全、法名字串乾淨或整列可訓練，亦不是全資料85%正確／15%錯誤。
