# 部署

平台的公開版本跑在組員自己的一台電腦上（主機名 `yuktoy`），透過 Tailscale Funnel 提供 HTTPS 網址：

**https://casey.tailf115eb.ts.net/**

main 的測試通過後，GitHub Actions 會在這台主機上自動部署新版。本機開發照舊用根目錄的 `docker compose up --build`，不受影響。

## 為什麼這樣部署

條件是**不在既有方案之外多花錢**。後端要把檢索索引和刑度模型讀進記憶體，實際約用 2.8 GB。2026-11 評估過的選項：

| 選項 | 結果 |
|---|---|
| Hugging Face Spaces | Docker Space 現在要付費方案（個人 PRO、組織 Team）才能建立 |
| Railway Hobby | 照用量計費，3 GB 常駐約每月 25～45 美元，超過含的 5 美元額度 |
| GCP Always Free | VM 只有 1 GB RAM；Cloud Run 冷啟動慢，映像儲存有小額費用 |
| Oracle Always Free | 規格夠，但註冊和搶機器常卡關，VM 要自己顧 |
| **自己的電腦 + Tailscale Funnel** | 0 元（電費除外），不需要固定 IP，不用開路由器的 port |

## 架構

```
使用者 ──HTTPS──▶ Tailscale Funnel ──▶ 主機 yuktoy（127.0.0.1:7860）
                                        └─ 容器 casey（deploy/server/Dockerfile）
                                            ├─ nginx：前端靜態檔；/api/ 轉給後端；頻率限制
                                            └─ uvicorn 127.0.0.1:8000（只跑一個程序）
                                                └─ 模型：啟動時從 HF 下載到 ~/casey/artifacts（重啟沿用）

GitHub（main 的 tests 通過）──▶ 主機上的自架 runner ──▶ deploy/server/deploy.sh
```

- 主機：Ubuntu Server 26.04 LTS，8 核、7 GB RAM、238 GB SSD，有線網路。
- 主機上的 `~/casey/`：`.env`（密鑰，不進 repo）、`artifacts/`（模型，約 4.5 GB）、`docker-compose.yml`（每次部署從 repo 複製）。
- 對外只有 Funnel 的 443。平台只綁 `127.0.0.1:7860`，區網和 tailnet 的其他裝置也連不到；SSH 只接受金鑰。

相關檔案：

| 檔案 | 用途 |
|---|---|
| `deploy/server/Dockerfile` | 前後端合成一個映像 |
| `deploy/server/start.sh` | 容器啟動：下載模型 → 啟動後端 → 後端載入完才開 nginx |
| `deploy/server/nginx.conf` | 聽 7860、取使用者真實 IP、gzip、快取、API 頻率限制 |
| `deploy/server/docker-compose.yml` | 資源上限、權限收緊、唯讀、log 交給主機的 journald |
| `deploy/server/.env.example` | 主機 `~/casey/.env` 的範本 |
| `deploy/server/deploy.sh` | 建映像 → 換新版 → 檢查四項模型 → 失敗換回上一版 |
| `deploy/server/setup-host.sh` | 主機初始設定：Docker、Tailscale、擴大硬碟 |
| `deploy/server/harden-host.sh` | 主機安全設定：SSH、容器出站限制、顯示卡卡死的修正 |
| `deploy/server/install-runner.sh` | 安裝 GitHub Actions 自架 runner |
| `.github/workflows/deploy.yml` | main 的 tests 通過後自動部署 |
| `scripts/sync_*.sh` | 下載模型（本機和主機共用） |

## 日常操作

在自己的電腦上（已經設好 `ssh yuktoy`，見下方「從頭架一台」第 3 步）：

| 要做的事 | 做法 |
|---|---|
| 部署新版程式 | 合併進 main 就好，tests 通過後自動部署。到 GitHub 的 Actions → deploy 看結果 |
| 手動重新部署 | GitHub 的 Actions → deploy → Run workflow（只能選 main） |
| 換模型版本 | 改主機 `~/casey/.env` 的 `JD_HF_REVISION`，再手動重新部署，或執行 `ssh yuktoy "cd ~/casey && docker compose up -d --force-recreate"` |
| 看 log | `ssh yuktoy "journalctl -t casey -f --since -10min"`（Ctrl + C 離開） |
| 看某段時間的 log | `ssh yuktoy "journalctl -t casey --since '2026-11-14 13:00' --until '2026-11-14 15:00'"` |
| 看誰連過 | `ssh yuktoy "journalctl -t casey --since -1day -o cat \| awk 'NF==4 {print \$1}' \| sort \| uniq -c \| sort -rn \| head"` |
| 看狀態 | `curl https://casey.tailf115eb.ts.net/api/health` |
| 重開平台 | `ssh yuktoy "cd ~/casey && docker compose restart"` |
| 重開主機 | `ssh -t yuktoy "sudo reboot"`，平台和 Funnel 會自己回來 |

**部署失敗時**，`deploy.sh` 會自動換回上一版，GitHub 上那次 deploy 會顯示失敗，log 裡有新版容器最後 40 行輸出。

**換模型的注意事項**：`JD_HF_REVISION` 指到的那一版，必須有後端要讀的所有資料夾（例如 A1 合併後民事檢索改讀 `retrieval_civil_v4`）。少了的話 `/api/health` 會顯示 `mock`，部署會失敗並換回上一版。

## 驗收：確認上線的是真的模型

`/api/health` 四個欄位都要是真的模型（`deploy.sh` 每次部署都會檢查）：

| 欄位 | 要看到 | 如果是別的值 |
|---|---|---|
| `civil` | `model` | `mock`：民事模型或檢索沒下載到 |
| `amount` | `model` | `similar`：金額模型沒下載到，改用相似判決估 |
| `criminal` | `model` | `mock`：刑事模型或檢索沒下載到 |
| `criminal_sentence` | `electra` | `svm`：刑度 ELECTRA 沒下載到 |

2026-11-14 上線時的驗收結果：四項都正確，模型版本 `fd862a0c15c9cfeca028ae0e6bde82ba48ecd3bd`；主機重開機後平台與 Funnel 自動恢復；手機用行動網路連得到，log 記到的是手機的對外 IP。

## 限制與保護

| 項目 | 設定 | 在哪裡 |
|---|---|---|
| API 頻率 | 每個 IP 每分鐘 30 次（可短暫衝到 20 次）、同時 10 條連線，超過回 429 | `nginx.conf` |
| LLM 用量 | 每個 IP 每小時 10 次、全站每天 300 次（記在後端記憶體，所以只跑一個程序） | `backend/llm/limits.py`、`.env` |
| 輸入長度 | 每段文字最多 2 萬字 | `backend/schemas.py` |
| 資源 | 記憶體 5 GB、CPU 6 核、程序數 256 | `docker-compose.yml` |
| 容器權限 | 一般使用者、拿掉所有 capabilities、`no-new-privileges`、系統檔案唯讀 | `docker-compose.yml` |
| 容器出站 | 連不到區網（10/8、192.168/16）、tailnet（100.64/10）；只能連外部網路 | `harden-host.sh` |
| SSH | 只接受金鑰 | `harden-host.sh` |
| 系統更新 | 自動安裝安全更新（Ubuntu 預設開啟） | |
| Gemini 費用 | 在 Google AI Studio 的 Spend 頁面為這把 key 所在的專案設每月上限 | Google 那邊 |

**為什麼要限制容器出站**：上線前實測，容器連得到 tailnet 上組員筆電的檔案分享（445 port）。網站萬一有漏洞被利用，攻擊者就能從容器去試探其他電腦。現在容器只能連 HF 和 Gemini 這類外部服務。

**真實 IP**：使用者的連線經過 Funnel 和 docker 轉進來，nginx 從 `X-Forwarded-For` 取使用者的 IP（`set_real_ip_from` 信任內網位址）。LLM 每 IP 的上限和 API 頻率限制都靠這個。上線時用手機行動網路驗證過：log 記到的是手機的對外 IPv6。

**公開網址一上線就會有掃描程式來**：HTTPS 憑證會登記在公開的憑證透明度紀錄上，爬蟲和掃描程式幾分鐘內就會來看首頁，這是正常的。log 裡看到某個 IP 一直被 429 擋下，表示頻率限制有在運作。

## Log 與隱私

**log 不含使用者輸入的內容**（2026-11-14 檢查過）：

- nginx 只記 IP、方法、路徑（不含查詢字串）和狀態碼。案情在 POST 的內容裡，不會被記。路徑是使用者原本要求的（例如掃描程式試的 `/.env`），不是改寫後的 `/index.html`。
- uvicorn 的存取紀錄也只有路徑和狀態碼。
- LLM 失敗時只記「HTTP 狀態碼」「無法連線」這類文字；LLM 用量只記 token 數和秒數（`backend/llm/gemini.py`、`openai_client.py`）。
- log 由 docker 交給主機的 journald（`docker-compose.yml` 的 `logging`），重新部署、容器重建都不會不見。最多保留 30 天、1 GB，舊的自動刪除（`harden-host.sh` 的第 3 步；整台主機的系統紀錄也一樣保留 30 天）。

之後新增 log 時要守同樣的原則：**不記使用者輸入的文字，也不記 LLM 的回應內容**。前端的「隱私與資料使用」頁（`/privacy`）也寫了這些，改了這裡要一起改。

## 遇過的問題

| 狀況 | 原因 | 處理 |
|---|---|---|
| 下載完 `/api/health` 還是 `mock` | 映像裡的 `hf` 是 0.x 版，`--include` 寫好幾次時只有最後一個有效 | `scripts/sync_*.sh` 改成每個資料夾各下載一次 |
| SSH 登入後卡住、`sudo` 卡住、Ctrl + C 沒反應，load 很高但 CPU 閒置 | NVIDIA 顯示卡的 `nouveau` 驅動在喚醒顯示卡時卡死，`fwupd` 去開顯示卡時觸發；一批程序卡在 D 狀態 | 只能實體按電源鍵重開。`harden-host.sh` 加開機參數 `nouveau.runpm=0` 並停用 `fwupd`。再發生時用 `journalctl -k -b` 查 `blocked for more than` |
| 部署時 `npm ci` 卡很久後出現 `Exit handler never called!`，接著 `tsc: not found` | 擋容器連區網的規則也擋掉了建置容器用路由器查 DNS（執行中的平台走 docker 內建 DNS，不受影響） | `harden-host.sh` 讓 docker 改用公開 DNS（`/etc/docker/daemon.json` 的 `dns`）。檢查：`docker run --rm casey:current python3 -c "import socket;print(socket.gethostbyname('pypi.org'))"` |
| 容器出站限制沒效（還連得到 tailnet） | 規則放在 `DOCKER-USER`，但 Tailscale 的 `ts-forward` 排在前面先放行 | 改放 `raw` 表的 `PREROUTING` |
| 手機第一次打開很慢 | 前端 JS 570 KB 沒壓縮 | nginx 開 gzip（約 190 KB）、`/assets/` 長期快取 |
| 從 Windows 用 `curl -d` 送中文測試，伺服器判斷成「不像法律糾紛」 | Windows 終端機把中文編碼弄亂 | 用 UTF-8 檔案送：`curl --data-binary @request.json` |

## 從頭架一台

照順序做，大約 1～2 小時（大多是等下載）。

### 1. 安裝 Ubuntu Server

- 下載 Ubuntu Server 26.04 LTS 的 ISO，用 Rufus 寫進隨身碟（分割配置用預設的 MBR 即可），從隨身碟開機（開機選單選有「UEFI」字樣的）。
- 安裝時：硬碟選 **Use an entire disk**；**勾選 Install OpenSSH server**；額外套件（snaps）都不要選。
- 裝完用 `hostname -I` 查區網 IP。

### 2. 主機初始設定

把 `deploy/server/setup-host.sh`、`harden-host.sh` 複製到主機（例如 `scp`），然後：

```bash
sudo bash setup-host.sh      # Docker、Tailscale、擴大硬碟；結束後 exit 再重新登入
```

### 3. SSH 金鑰（在自己的電腦）

```powershell
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\yuktoy_ed25519
type $env:USERPROFILE\.ssh\yuktoy_ed25519.pub | ssh <帳號>@<區網IP> "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

在 `~/.ssh/config` 加：

```
Host yuktoy
    HostName <區網IP>
    User <帳號>
    IdentityFile ~/.ssh/yuktoy_ed25519
    IdentitiesOnly yes
```

確認 `ssh yuktoy` 不用密碼就能登入，**再**做下一步（下一步會關掉密碼登入）。

### 4. 安全設定

```powershell
ssh -t yuktoy "sudo bash ~/harden-host.sh"
ssh -t yuktoy "sudo reboot"
```

`sudo` 的密碼提示有時不會顯示，畫面停住時直接輸入密碼再按 Enter。

### 5. Tailscale 與 Funnel

```powershell
ssh -t yuktoy "sudo tailscale up --hostname=casey --operator=<帳號>"
```

- 打開印出的網址登入 Tailscale。tailnet 有開裝置核准的話，到管理頁面 Machines 核准 `casey`。
- 同一個選單按 **Disable key expiry**，不然 180 天後網址會斷。
- 開 Funnel：`ssh yuktoy "tailscale funnel --bg 7860"`。第一次會給一個網址，要到網頁上同意開啟 Funnel。

### 6. 密鑰

- HF：到 https://huggingface.co/settings/tokens 建一把 **Fine-grained** token，只勾 `JudgementDigest/judgementdigest-artifacts` 的 **Read access to contents**。
- Gemini：建議伺服器專用一把 key，並在 Google AI Studio 的 Spend 頁面設每月上限。

```powershell
ssh yuktoy "mkdir -p ~/casey && umask 077 && touch ~/casey/.env"
ssh -t yuktoy "nano ~/casey/.env"     # 內容照 deploy/server/.env.example 填
```

`JD_HF_REVISION` 填模型 repo 要上線那一版的 commit（https://huggingface.co/JudgementDigest/judgementdigest-artifacts/commits/main）。

### 7. 第一次部署

```powershell
ssh yuktoy "git clone https://github.com/yuzuEN/JudgementDigest.git ~/JudgementDigest && bash ~/JudgementDigest/deploy/server/deploy.sh"
```

第一次要下載約 5 GB 的模型，`deploy.sh` 最多等 20 分鐘。成功會印出 `/api/health`。

### 8. 自動部署（自架 runner）

1. GitHub repo → **Settings → Actions → General**，「Fork pull request workflows from outside collaborators」選 **Require approval for all external contributors**。repo 是公開的，不設的話陌生人開 PR 改 workflow，就可能在主機上執行指令。
2. GitHub repo → **Settings → Actions → Runners → New self-hosted runner**，選 Linux，複製頁面上 `./config.sh` 那行的 `--token` 值（一小時內有效）。
3. 把 `deploy/server/install-runner.sh` 複製到主機後執行：

   ```powershell
   ssh -t yuktoy "bash ~/install-runner.sh <token>"
   ```

4. Runners 頁面看到 `casey` 是 Idle 就好了。到 Actions → deploy → Run workflow 手動跑一次確認。
