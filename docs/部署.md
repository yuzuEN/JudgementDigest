# 部署

平台的公開版本跑在組員自己的一台電腦上（主機名 `yuktoy`），透過 Tailscale Funnel 提供 HTTPS 網址：

**https://casey.tailf115eb.ts.net/**

目前**還沒公開**（Funnel 關著，只有 tailnet 裡的裝置連得到），自動部署也還關著（程式已經準備好）；新版要在主機上手動部署。系統準備好要公開時再打開 Funnel 和自動部署（見「從頭架一台」第 8 步）。本機開發照舊用根目錄的 `docker compose up --build`，不受影響。

**2026-11-18 起主機本身不在 tailnet 上**：tailnet 連線改由 `ts-casey` 容器（`tag:casey`）負責，tailnet 上只看得到平台，看不到主機；管理主機（SSH）只能從區網連。

## 為什麼這樣部署

條件是**不在既有方案之外多花錢**。後端要把檢索索引和刑度模型讀進記憶體，實際約用 2.8 GB。2026-11 評估過的選項：

| 選項 | 結果 |
|---|---|
| Hugging Face Spaces | Docker Space 現在要付費方案（個人 PRO、組織 Team）才能建立 |
| Railway Hobby | 照用量計費，3 GB 常駐約每月 25～45 美元，超過含的 5 美元額度 |
| GCP Always Free | VM 只有 1 GB RAM；Cloud Run 冷啟動慢，映像儲存有小額費用 |
| Oracle Always Free | 規格夠，但註冊和搶機器常卡關，VM 要自己顧 |
| **自己的電腦 + Tailscale Funnel** | 0 元（電費除外），不需要固定 IP，不用開路由器的 port |

## 架構

```
使用者 ──HTTPS──▶ tailnet／Tailscale Funnel ──▶ 容器 ts-casey（tag:casey，tailnet 名稱 casey，443 轉給 127.0.0.1:7860）
                                                 └─ 容器 casey（共用 ts-casey 的網路；deploy/server/Dockerfile）
                                                     ├─ nginx：前端靜態檔；/api/ 轉給後端；頻率限制
                                                     └─ uvicorn 127.0.0.1:8000（只跑一個程序）
                                                         └─ 模型：啟動時從 HF 下載到 ~/casey/artifacts（重啟沿用）

管理：區網 ──SSH──▶ 主機 yuktoy（固定 IP 192.168.50.85；不在 tailnet 上）
部署：在主機上 git pull ──▶ deploy/server/deploy.sh（建新版、檢查模型、失敗換回上一版）
```

- 主機：Ubuntu Server 26.04 LTS，8 核、7 GB RAM、238 GB SSD，有線網路。
- 主機上的 `~/casey/`：`.env`（密鑰，不進 repo）、`ts.env`（ts-casey 第一次登入用的 auth key，登入後清空）、`ts-state/`（ts-casey 的節點身分）、`artifacts/`（模型，約 4.5 GB）、`docker-compose.yml` 和 `ts-serve*.json`（每次部署從 repo 複製）。
- tailnet 上只有 ts-casey，而且只開 443（`tailscale-policy.hujson`）；`tag:casey` 不能主動連 tailnet 上的任何裝置。主機的 SSH 不在 tailnet 上，只能從區網連，而且只接受金鑰。
- 平台在主機上只綁 `127.0.0.1:7860`（給 `deploy.sh` 的健康檢查和本機 `curl` 用），區網連不到。

相關檔案：

| 檔案 | 用途 |
|---|---|
| `deploy/server/Dockerfile` | 前後端合成一個映像 |
| `deploy/server/start.sh` | 容器啟動：下載模型 → 啟動後端 → 後端載入完才開 nginx |
| `deploy/server/nginx.conf` | 聽 7860、取使用者真實 IP、gzip、快取、API 頻率限制 |
| `deploy/server/docker-compose.yml` | ts-casey（tailnet）＋ casey（平台）；資源上限、權限收緊、唯讀、log 交給主機的 journald |
| `deploy/server/ts-serve.json`、`ts-serve-funnel.json` | ts-casey 把 443 轉給平台：只給 tailnet（預設）／也公開到網際網路（Funnel） |
| `deploy/server/tailscale-policy.hujson` | Tailscale 存取政策（手動貼到管理頁面，不會自動套用） |
| `deploy/server/.env.example` | 主機 `~/casey/.env` 的範本 |
| `deploy/server/deploy.sh` | 建映像 → 換新版 → 檢查四項模型 → 失敗換回上一版 |
| `deploy/server/auto-deploy.sh` | 自動部署：main 有新的 commit、tests 通過，就執行 `deploy.sh`（每 5 分鐘一次） |
| `deploy/server/auto-deploy-setup.sh` | 打開／關掉自動部署（預設關） |
| `deploy/server/setup-host.sh` | 主機初始設定：Docker、擴大硬碟（主機不裝 Tailscale） |
| `deploy/server/harden-host.sh` | 主機安全設定：SSH、容器出站限制、顯示卡卡死的修正 |
| `scripts/sync_*.sh` | 下載模型（本機和主機共用） |

## 日常操作

在自己的電腦上，**連在同一個區網時**（已經設好 `ssh yuktoy`，見下方「從頭架一台」第 3 步；主機不在 tailnet 上，外面連不到）：

| 要做的事 | 做法 |
|---|---|
| 部署新版程式（main） | 先確認 GitHub 上 main 的 tests 通過，再執行 `ssh yuktoy "cd ~/JudgementDigest && git pull && bash deploy/server/deploy.sh"`。失敗會自動換回上一版 |
| 打開／關掉公開網址 | 打開：在主機 `~/casey/.env` 加一行 `CASEY_SERVE_CONFIG=ts-serve-funnel.json`；關掉：刪掉那一行。改完執行 `ssh yuktoy "cd ~/casey && docker compose up -d"`。狀態：`ssh yuktoy "cd ~/casey && docker compose exec ts-casey tailscale --socket=/tmp/tailscaled.sock serve status"`（看到 `(Funnel on)` 就是公開）。第一次打開前要先做「從頭架一台」第 8 步的存取政策設定 |
| 看 tailnet 連線狀態 | `ssh yuktoy "cd ~/casey && docker compose exec ts-casey tailscale --socket=/tmp/tailscaled.sock status"`；log：`journalctl -t casey-ts` |
| 換模型版本 | 改主機 `~/casey/.env` 的 `JD_HF_REVISION`，再執行 `ssh yuktoy "cd ~/casey && docker compose up -d --force-recreate"` |
| 看 log | `ssh yuktoy "journalctl -t casey -f --since -10min"`（Ctrl + C 離開） |
| 看某段時間的 log | `ssh yuktoy "journalctl -t casey --since '2026-11-14 13:00' --until '2026-11-14 15:00'"` |
| 看誰連過 | `ssh yuktoy "journalctl -t casey --since -1day -o cat \| awk 'NF==4 {print \$1}' \| sort \| uniq -c \| sort -rn \| head"` |
| 看狀態 | `curl https://casey.tailf115eb.ts.net/api/health` |
| 重開平台 | `ssh yuktoy "cd ~/casey && docker compose restart"` |
| 重開主機 | `ssh -t yuktoy "sudo reboot"`，平台和 ts-casey（含 Funnel）會自己回來 |

**部署失敗時**，`deploy.sh` 會自動換回上一版，並印出新版容器最後 40 行輸出。

**換模型的注意事項**：`JD_HF_REVISION` 指到的那一版，必須有後端要讀的所有資料夾（例如 A1 合併後民事檢索改讀 `retrieval_civil_v4`）。少了的話 `/api/health` 會顯示 `mock`，部署會失敗並換回上一版。

## 驗收：確認上線的是真的模型

`/api/health` 四個欄位都要是真的模型（`deploy.sh` 每次部署都會檢查）：

| 欄位 | 要看到 | 如果是別的值 |
|---|---|---|
| `civil` | `model` | `mock`：民事模型或檢索沒下載到 |
| `amount` | `model` | `similar`：金額模型沒下載到，改用相似判決估 |
| `criminal` | `model` | `mock`：刑事模型或檢索沒下載到 |
| `criminal_sentence` | `electra` | `svm`：刑度 ELECTRA 沒下載到 |

2026-11-14 上線時的驗收結果：四項都正確，模型版本 `fd862a0c15c9cfeca028ae0e6bde82ba48ecd3bd`；主機重開機後平台與 Funnel 自動恢復；手機用行動網路連得到，log 記到的是手機的對外 IP。

## 限制與保護

| 項目 | 設定 | 在哪裡 |
|---|---|---|
| API 頻率 | 每個 IP 每分鐘 30 次（可短暫衝到 20 次）、同時 10 條連線，超過回 429 | `nginx.conf` |
| LLM 用量 | 每個 IP 每小時 10 次、全站每天 300 次（記在後端記憶體，所以只跑一個程序） | `backend/llm/limits.py`、`.env` |
| 輸入長度 | 每段文字最多 2 萬字 | `backend/schemas.py` |
| 資源 | 記憶體 5 GB、CPU 6 核、程序數 256 | `docker-compose.yml` |
| 容器權限 | 一般使用者、拿掉所有 capabilities、`no-new-privileges`、系統檔案唯讀 | `docker-compose.yml` |
| 容器出站 | 連不到區網（10/8、192.168/16）、tailnet（100.64/10）；只能連外部網路 | `harden-host.sh` |
| tailnet | 只有 ts-casey（`tag:casey`）在 tailnet 上，只開 443；`tag:casey` 不能主動連任何裝置；主機不在 tailnet 上 | `tailscale-policy.hujson`、`docker-compose.yml` |
| SSH | 只接受金鑰；只能從區網連 | `harden-host.sh` |
| 系統更新 | 自動安裝安全更新（Ubuntu 預設開啟） | |
| Gemini 費用 | 在 Google AI Studio 的 Spend 頁面為這把 key 所在的專案設每月上限 | Google 那邊 |

**為什麼要限制容器出站**：上線前實測，容器連得到 tailnet 上組員筆電的檔案分享（445 port）。網站萬一有漏洞被利用，攻擊者就能從容器去試探其他電腦。現在容器只能連 HF 和 Gemini 這類外部服務。

**真實 IP**：使用者的連線經過 ts-casey 轉進來（平台看到的來源是 `127.0.0.1`），nginx 從 `X-Forwarded-For` 取使用者的 IP（`set_real_ip_from` 信任內網位址和 `127.0.0.1`）。LLM 每 IP 的上限和 API 頻率限制都靠這個。上線時用手機行動網路驗證過：log 記到的是手機的對外 IPv6。2026-11-18 改成 ts-casey 後，從 tailnet 連進來的 log 記到的是那台裝置的 tailnet IP；Funnel 打開後要再用手機行動網路驗證一次。

**為什麼主機不在 tailnet 上**：以前主機自己加入 tailnet，SSH 聽在所有網卡上，tailnet 裡的裝置都連得到主機的 SSH；存取政策設錯一條，或 tailnet 裡任何一台裝置被入侵，都會波及主機。現在 tailnet 上只有 ts-casey 這個容器，它沒有 SSH，也不能主動往外連；主機的管理只走區網。

**公開網址一上線就會有掃描程式來**：HTTPS 憑證會登記在公開的憑證透明度紀錄上，爬蟲和掃描程式幾分鐘內就會來看首頁，這是正常的。log 裡看到某個 IP 一直被 429 擋下，表示頻率限制有在運作。

## Log 與隱私

**log 不含使用者輸入的內容**（2026-11-14 檢查過）：

- nginx 只記 IP、方法、路徑（不含查詢字串）和狀態碼。案情在 POST 的內容裡，不會被記。路徑是使用者原本要求的（例如掃描程式試的 `/.env`），不是改寫後的 `/index.html`。
- uvicorn 的存取紀錄也只有路徑和狀態碼。
- LLM 失敗時只記「HTTP 狀態碼」「無法連線」這類文字；LLM 用量只記 token 數和秒數（`backend/llm/gemini.py`、`openai_client.py`）。
- log 由 docker 交給主機的 journald（`docker-compose.yml` 的 `logging`），重新部署、容器重建都不會不見。最多保留 30 天、1 GB，舊的自動刪除（`harden-host.sh` 的第 3 步；整台主機的系統紀錄也一樣保留 30 天）。

之後新增 log 時要守同樣的原則：**不記使用者輸入的文字，也不記 LLM 的回應內容**。前端的「隱私與資料使用」頁（`/privacy`）也寫了這些，改了這裡要一起改。

## 遇過的問題

| 狀況 | 原因 | 處理 |
|---|---|---|
| 下載完 `/api/health` 還是 `mock` | 映像裡的 `hf` 是 0.x 版，`--include` 寫好幾次時只有最後一個有效 | `scripts/sync_*.sh` 改成每個資料夾各下載一次 |
| SSH 登入後卡住、`sudo` 卡住、Ctrl + C 沒反應，load 很高但 CPU 閒置 | NVIDIA 顯示卡的 `nouveau` 驅動在喚醒顯示卡時卡死，`fwupd` 去開顯示卡時觸發；一批程序卡在 D 狀態 | 只能實體按電源鍵重開。`harden-host.sh` 加開機參數 `nouveau.runpm=0` 並停用 `fwupd`。再發生時用 `journalctl -k -b` 查 `blocked for more than` |
| 部署時 `npm ci` 卡很久後出現 `Exit handler never called!`，接著 `tsc: not found` | 擋容器連區網的規則也擋掉了建置容器用路由器查 DNS（執行中的平台走 docker 內建 DNS，不受影響） | `harden-host.sh` 讓 docker 改用公開 DNS（`/etc/docker/daemon.json` 的 `dns`）。檢查：`docker run --rm casey:current python3 -c "import socket;print(socket.gethostbyname('pypi.org'))"` |
| 容器出站限制沒效（還連得到 tailnet） | 規則放在 `DOCKER-USER`，但 Tailscale 的 `ts-forward` 排在前面先放行 | 改放 `raw` 表的 `PREROUTING` |
| ts-casey 每次重啟都變成新的節點（新 IP、名稱變成 `casey-1`） | 用 root 加 `cap_drop: ALL` 執行時，root 改不了主機帳號的 `ts-state/`，log 出現 `store.New failed ... starting with in-memory store` | ts-casey 改用主機帳號的 UID 執行（`user: "${CASEY_UID}:${CASEY_GID}"`，`deploy.sh` 會設定） |
| 換成 ts-casey 版時 `port is already allocated` | 舊版的 casey 還綁著 `127.0.0.1:7860`，新的 ts-casey 綁不到 | `deploy.sh` 偵測到舊版網路設定時會先 `docker compose down` |
| 同一個區網裡的筆電連 casey 很慢（`tailscale ping casey` 顯示 `via DERP`） | 容器出站限制擋掉了 ts-casey 連區網，沒辦法區網直連，只能走 DERP 中繼（多約 200 ms） | 預期中的取捨，不處理；外面的使用者不受影響 |
| 手機第一次打開很慢 | 前端 JS 570 KB 沒壓縮 | nginx 開 gzip（約 190 KB）、`/assets/` 長期快取 |
| 從 Windows 用 `curl -d` 送中文測試，伺服器判斷成「不像法律糾紛」 | Windows 終端機把中文編碼弄亂 | 用 UTF-8 檔案送：`curl --data-binary @request.json` |

## 從頭架一台

照順序做，大約 1～2 小時（大多是等下載）。

### 1. 安裝 Ubuntu Server

- 下載 Ubuntu Server 26.04 LTS 的 ISO，用 Rufus 寫進隨身碟（分割配置用預設的 MBR 即可），從隨身碟開機（開機選單選有「UEFI」字樣的）。
- 安裝時：硬碟選 **Use an entire disk**；**勾選 Install OpenSSH server**；額外套件（snaps）都不要選。
- 裝完用 `hostname -I` 查區網 IP。

### 2. 主機初始設定

把 `deploy/server/setup-host.sh`、`harden-host.sh` 複製到主機（例如 `scp`），然後：

```bash
sudo bash setup-host.sh      # Docker、擴大硬碟；結束後 exit 再重新登入
```

### 3. SSH 金鑰（在自己的電腦）

```powershell
ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\yuktoy_ed25519
type $env:USERPROFILE\.ssh\yuktoy_ed25519.pub | ssh <帳號>@<區網IP> "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

在 `~/.ssh/config` 加：

```
Host yuktoy
    HostName <區網IP>
    User <帳號>
    IdentityFile ~/.ssh/yuktoy_ed25519
    IdentitiesOnly yes
```

確認 `ssh yuktoy` 不用密碼就能登入，**再**做下一步（下一步會關掉密碼登入）。

### 4. 安全設定

```powershell
ssh -t yuktoy "sudo bash ~/harden-host.sh"
ssh -t yuktoy "sudo reboot"
```

`sudo` 的密碼提示有時不會顯示，畫面停住時直接輸入密碼再按 Enter。

### 5. Tailscale（給 ts-casey 容器，不是給主機）

主機本身不加入 tailnet。這一步只是讓第 7 步啟動的 ts-casey 容器能登入。

1. **存取政策**：Tailscale 管理頁面 → **Access controls** → **JSON editor**，先把原本的內容另存一份，再換成 `deploy/server/tailscale-policy.hujson` 的內容，按 Save。
2. **auth key**：管理頁面 → **Settings → Keys → Generate auth key**。Description 寫例如 `casey sidecar on yuktoy`；Reusable 關、Ephemeral 關、Expiration 1 天、Pre-approved 開（有這個選項的話）、Tags 選 `tag:casey`。
3. 在主機上建立 `~/casey/ts.env`，**自己**貼上 key（不要貼到聊天或其他地方）：

```powershell
ssh yuktoy "mkdir -p ~/casey && umask 077 && touch ~/casey/ts.env"
ssh -t yuktoy "nano ~/casey/ts.env"     # 只有一行：TS_AUTHKEY=tskey-auth-...
```

- 帶 tag 的節點不會因為金鑰到期而登出，不用 Disable key expiry。
- 第 7 步部署成功、`tailscale status` 看得到 `casey` 之後，可以把 `ts.env` 清空（`ssh yuktoy ": > ~/casey/ts.env"`）：節點身分已經存在 `~/casey/ts-state/`。
- 主機以前裝過 Tailscale 的話，先讓它退出：`sudo tailscale logout`、`sudo systemctl disable --now tailscaled`，再到 Machines 刪掉舊的 `casey`，名稱才空得出來（不然新的會變成 `casey-1`）。

### 6. 密鑰

- HF：到 https://huggingface.co/settings/tokens 建一把 **Fine-grained** token，只勾 `JudgementDigest/judgementdigest-artifacts` 的 **Read access to contents**。
- Gemini：建議伺服器專用一把 key，並在 Google AI Studio 的 Spend 頁面設每月上限。

```powershell
ssh yuktoy "mkdir -p ~/casey && umask 077 && touch ~/casey/.env"
ssh -t yuktoy "nano ~/casey/.env"     # 內容照 deploy/server/.env.example 填
```

`JD_HF_REVISION` 填模型 repo 要上線那一版的 commit（https://huggingface.co/JudgementDigest/judgementdigest-artifacts/commits/main）。

### 7. 第一次部署

```powershell
ssh yuktoy "git clone https://github.com/yuzuEN/JudgementDigest.git ~/JudgementDigest && bash ~/JudgementDigest/deploy/server/deploy.sh"
```

第一次要下載約 5 GB 的模型，`deploy.sh` 最多等 20 分鐘。成功會印出 `/api/health`。之後在自己的電腦（要在 tailnet 上）打開 `https://casey.<tailnet>.ts.net/` 確認連得到。

### 8. 之後要公開時

1. 打開 Funnel：
   - 存取政策（`tailscale-policy.hujson`）把最下面註解掉的 `nodeAttrs` 那段打開（讓 `tag:casey` 可以用 Funnel），貼回管理頁面儲存。
   - 主機 `~/casey/.env` 加一行 `CASEY_SERVE_CONFIG=ts-serve-funnel.json`，再執行 `ssh yuktoy "cd ~/casey && docker compose up -d"`。
   - 確認：`serve status` 顯示 `(Funnel on)`；用手機行動網路（不在 tailnet 上）打開網址，並確認 log 記到的是手機的對外 IP。
2. 打開自動部署：`ssh -t yuktoy "sudo bash ~/JudgementDigest/deploy/server/auto-deploy-setup.sh on"`。之後 main 的 tests 通過，最多 5 分鐘內就會部署。
   - 看狀態：`ssh yuktoy "bash ~/JudgementDigest/deploy/server/auto-deploy-setup.sh status"`；看紀錄：`ssh yuktoy "journalctl -u casey-auto-deploy --since -1day"`。
   - 關掉：把 `on` 換成 `off`。
   - 同一個 commit 只處理一次；tests 失敗或部署失敗都不會重試，下一個 commit 再試。要重試同一個 commit：`ssh yuktoy "rm ~/casey/auto-deploy.state"`。
   - 為什麼不用 GitHub Actions 的自架 runner：repo 是公開的，陌生人開的 PR 可能讓 runner 在主機上執行指令，而 runner 的帳號在 docker 群組裡，等於主機的管理員。現在的做法是主機自己 `git fetch` main、查 tests 結果（都是公開資訊，不用帳號或密鑰），GitHub 完全不能在主機上執行東西。
3. GitHub repo → **Settings → Actions → General**，「Fork pull request workflows from outside collaborators」選 **Require approval for all external contributors**（公開 repo 一般都建議這樣設）。
